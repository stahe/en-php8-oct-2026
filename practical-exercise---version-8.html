    18. Practical exercise – version 8

    We are going to take the example application – version 5 (and its version 7, configured by a JSON file) and turn it into a client / server application. In this way we put into practice what we learned in the previous chapter about web services.

    18.1. Introduction

    The architecture of version 5 was as follows:

    • the layer called [dao] (Data Access Objects) handles exchanges with the MySQL database and the local file system;
    • the layer called [métier] performs the tax calculation;
    • the main script is the conductor: it instantiates the [dao] and [métier] layers and then talks to the [métier] layer to do what needs to be done.

    We are going to migrate this architecture to the following client / server architecture:

    • in [2], we will reuse the [dao] layer of version 5, removing its methods for accessing the local file system. These methods will migrate to the client's [dao] layer [6, 7];
    • in [3], the [métier] layer will remain that of version 5 without its [executeBatchImpots] method, which migrates to the client's [métier] layer [8];
    • in [4], the server script has to be written: it will have to:
      • create the [métier] and [dao] layers [3, 2];
      • talk to the client script [5, 7];
    • in [7], the client's [dao] layer has to be written:
      • it will be an HTTP client of the server script [4, 5];
      • it will reuse the local file system access methods of the [dao] layer of version 5;
    • in [8], the client's [métier] layer will offer the same methods as the [InterfaceMetier] interface of version 5. Its implementation will however be different. In version 5, the [métier] layer performed the tax calculation. Here, it is the server's [métier] layer that performs this calculation. The client's [métier] layer will therefore call on the [dao] layer [7] to talk to the server and ask it to calculate the tax;
    • in [9], the console script will have to instantiate the client's [dao, métier] layers and start its execution.

    The server is a web script: it is placed in the [scripts-web/impots/version-08] folder and executed by the Apache server of [Laragon]. The client is a console script: it is placed in the [scripts-console/impots/version-08] folder and executed in a terminal.

    18.2.1. The entities exchanged between layers

    The entities exchanged between layers are those of version 5: the [ExceptionImpots] exception, the tax authority data [TaxAdminData] and the database description [Database]. The server also uses the [Utilitaires] class of version 5, whose [lireFichierJson] method is used by the [Database] class. The PHP 7 course copied these files into the server's folder. We load them directly from the [scripts-console/impots/version-05] folder: in this way a class exists in only one copy, and a fix made in version 5 benefits all the versions that use it.

    <?php

declare(strict_types=1);

// espace de noms
namespace Application;

// la couche [dao] du serveur : elle trouve les données de l'administration fiscale dans une base de données
// c'est la classe [DaoImpotsWithTaxAdminDataInDatabase] de la version 5 sans les méthodes
// qui travaillent avec les fichiers JSON des contribuables
class ServerDao implements InterfaceServerDao
{
    // la description de la base de données
    private readonly Database $database;
    // l'objet de type [TaxAdminData] qui contient les données de l'administration fiscale
    // [protected] : les classes dérivées pourront l'initialiser
    protected readonly TaxAdminData $taxAdminData;

    // le constructeur
    public function __construct(string $databaseFilename)
    {
        // la description de la base de données - peut lancer une exception [ExceptionImpots]
        $this->database = Database::fromJsonFile($databaseFilename);
        $database = $this->database;
        try {
            // on ouvre la connexion à la base de données
            // les lignes lues seront rendues sous la forme de tableaux associatifs [colonne => valeur]
            $connexion = \PDO::connect(
                $database->dsn,
                $database->id,
                $database->pwd,
                [\PDO::ATTR_DEFAULT_FETCH_MODE => \PDO::FETCH_ASSOC]
            );
            // on démarre une transaction
            $connexion->beginTransaction();
            // on lit la table des tranches d'impôt
            $tranches = $this->getTranches($connexion);
            // on lit la table des constantes
            $constantes = $this->getConstantes($connexion);
            // on termine la transaction sur un succès
            $connexion->commit();
        } catch (\PDOException $ex) {
            // y a-t-il une transaction en cours ?
            if (isset($connexion) && $connexion->inTransaction()) {
                // on termine la transaction sur un échec
                $connexion->rollBack();
            }
            // on remonte l'erreur au code appelant sous la forme d'une exception [ExceptionImpots]
            throw new ExceptionImpots("Erreur d'accès à la base de données ({$ex->getMessage()})", 30, $ex);
        }
        // construction de l'objet [TaxAdminData] : les données lues sont vérifiées
        $this->taxAdminData = TaxAdminData::fromArray([...$tranches, ...$constantes]);
    }

    This is the code of the [DaoImpotsWithTaxAdminDataInDatabase] class of version 5, presented in chapter 13, without the [TraitDao] trait that provided the methods for reading and writing the taxpayers' JSON files. The private methods [getTranches] and [getConstantes] that follow, not reproduced here, are unchanged. There is only one difference:

    • line 17: the [taxAdminData] attribute is declared [protected] and no longer [private]. Version 9 will derive the [ServerDao] class, and the derived class will need to be able to initialize this attribute. Since PHP 8.4, a derived class can initialize an inherited [readonly] attribute, provided it is not private.

The same goes for the [database-mysql.json] file, which contains the database password. The [Data] folder therefore contains a [.htaccess] file:

The [Require all denied] directive forbids access to the folder: Apache responds [403 Forbidden] to any request for a file in the [Data] folder. The PHP script, for its part, reads these files from disk without going through Apache and is not affected.

    <?php

// respect strict des types déclarés des paramètres et des résultats des fonctions
declare(strict_types=1);

// espace de noms
namespace Application;

// dépendances Symfony
use Symfony\Component\HttpFoundation\JsonResponse;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;

// le dossier racine du serveur : les chemins du fichier de configuration sont relatifs à ce dossier
const ROOT_DIRECTORY = __DIR__;
// chemin du fichier de configuration
const CONFIG_FILENAME = ROOT_DIRECTORY . "/Data/config-server.json";

// on récupère la configuration
$config = json_decode(file_get_contents(CONFIG_FILENAME), true, flags: JSON_THROW_ON_ERROR);

// on inclut les dépendances nécessaires au script
require_once ROOT_DIRECTORY . "/../../../vendor/autoload.php";
foreach ($config["dependencies"] as $dependency) {
    require_once ROOT_DIRECTORY . "/$dependency";
}

// préparation de la réponse JSON du serveur
$response = new JsonResponse();
// caractères accentués et / non échappés, réels toujours écrits avec un point décimal (0.0)
$response->setEncodingOptions(JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES | JSON_PRESERVE_ZERO_FRACTION);

// on récupère la requête courante
$request = Request::createFromGlobals();
// authentification : les identifiants envoyés par le client (null s'il n'en a pas envoyé)
$requestUser = $request->getUser();
$requestPassword = $request->getPassword();
// l'utilisateur fait-il partie des utilisateurs autorisés ?
$trouvé = $requestUser !== null && $requestPassword !== null
    && array_any(
        $config["users"],
        fn(array $user): bool => $user["login"] === $requestUser && hash_equals($user["passwd"], $requestPassword)
    );
if (!$trouvé) {
    // pas trouvé - code 401
    $response->setStatusCode(Response::HTTP_UNAUTHORIZED);
    $response->headers->set("WWW-Authenticate", 'Basic realm="Serveur de calcul des impots"');
    // message d'erreur
    $response->setData(["réponse" => ["erreur" => "Echec de l'authentification [$requestUser]"]]);
    $response->send();
    // fin
    exit;
}

// on a un utilisateur valide - on vérifie les paramètres reçus
$erreurs = [];
// on doit avoir une requête GET avec trois paramètres
if ($request->getMethod() !== "GET" || $request->query->count() !== 3) {
    $erreurs[] = "Méthode GET requise avec les seuls paramètres [marié, enfants, salaire]";
}
// le statut marital
if (!$request->query->has("marié")) {
    $erreurs[] = "paramètre marié manquant";
} else {
    $marié = strtolower(trim($request->query->getString("marié")));
    if (!in_array($marié, ["oui", "non"], true)) {
        $erreurs[] = "paramètre marié [$marié] invalide";
    }
}
// le nombre d'enfants et le salaire : des nombres entiers >= 0
$valeurs = [];
foreach (["enfants", "salaire"] as $paramètre) {
    if (!$request->query->has($paramètre)) {
        $erreurs[] = "paramètre $paramètre manquant";
        continue;
    }
    $valeur = trim($request->query->getString($paramètre));
    if (preg_match('/^\d+$/', $valeur) !== 1) {
        $erreurs[] = "paramètre $paramètre [$valeur] invalide";
    } else {
        $valeurs[$paramètre] = (int) $valeur;
    }
}
// autres paramètres dans la requête ?
foreach (array_diff(array_keys($request->query->all()), ["marié", "enfants", "salaire"]) as $paramètre) {
    $erreurs[] = "paramètre [$paramètre] invalide";
}
// erreurs ?
if ($erreurs !== []) {
    // on envoie un code d'erreur 400 au client
    $response->setStatusCode(Response::HTTP_BAD_REQUEST);
    $response->setData(["réponse" => ["erreurs" => $erreurs]]);
    $response->send();
    exit;
}

// on a tout ce qu'il faut pour travailler
// création de l'architecture du serveur
try {
    // création de la couche [dao]
    $dao = new ServerDao(ROOT_DIRECTORY . "/" . $config["databaseFilename"]);
    // création de la couche [métier]
    $métier = new ServerMetier($dao);
} catch (ExceptionImpots $ex) {
    // le message d'erreur d'un pilote de SGBD peut ne pas être codé en UTF-8 (Windows-1252 sous Windows)
    $message = $ex->getMessage();
    if (!mb_check_encoding($message, "UTF-8")) {
        $message = mb_convert_encoding($message, "UTF-8", "Windows-1252");
    }
    // on envoie un code d'erreur 500 au client
    $response->setStatusCode(Response::HTTP_INTERNAL_SERVER_ERROR);
    $response->setData(["réponse" => ["erreur" => $message]]);
    $response->send();
    exit;
}
// calcul de l'impôt
$result = $métier->calculerImpot($marié, $valeurs["enfants"], $valeurs["salaire"]);
// on rend la réponse
$response->setData(["réponse" => $result]);
$response->send();

    Comments

    • lines 10-12: we declare the classes of the [HttpFoundation] library that we are going to use;
    • line 15: the server's root folder is the script's folder;
    • line 20: we use the configuration file;
    • lines 23-26: we load [Composer]'s class loader, then all the application's files;
    • line 29: we prepare a JSON response. The [JsonResponse] class is a class derived from [Response]: its [setData] method encodes the array it is given as JSON and makes it the response document. It also sets the HTTP header [Content-Type: application/json];
    • line 31: the options of the [json_encode] function used by [setData]. With [JSON_UNESCAPED_UNICODE], accented characters are not encoded as [\uXXXX]. With [JSON_PRESERVE_ZERO_FRACTION], the real tax rate [0.0] is written [0.0] and not [0]: the client will decode it as a real number (float) and not as an integer;
    • lines 36-37: we retrieve the credentials sent by the client, as in the previous chapter;
    • lines 39-43: we check that the user is indeed one of the authorized users. The [array_any] function (PHP 8.4) returns [true] if at least one of the elements of the [$config["users"]] array satisfies the condition expressed by the arrow function passed to it. It replaces the [while] loop of the PHP 7 script. The passwords are compared with [hash_equals];
    • lines 44-52: if not, we send the HTTP code [401 Unauthorized], which indicates that access is refused. On receiving this code and the HTTP header [WWW-Authenticate: Basic realm=…], browsers display an authentication window inviting the user to log in;
    • line 49: the server's JSON response explains the cause of the error ("Echec de l'authentification": authentication failed). All the server's responses will be the JSON string of an array [["réponse" => qqChose]]. The PHP 7 script sent the rejected login and password back to the client. A password must never be sent back, nor written to logs: we only send back the login;
    • lines 56-88: we check the validity of the request:
      • a GET request with exactly three parameters;
      • a [marié] parameter whose value must be [oui] or [non];
      • an [enfants] parameter whose value must be an integer >= 0;
      • a [salaire] parameter whose value must be an integer >= 0;
      • no other parameter;
    • line 59: each time an error is detected, an error message is added to the [$erreurs] array;
    • line 65: the [getString] method of the [$request->query] object returns the value of the parameter as a string;
    • line 72: the [enfants] and [salaire] parameters obey the same rule: we check them in the same loop. Their values, converted to integers, are placed in the [$valeurs] array;
    • line 85: the [array_diff] function returns the names of the parameters received that are not in the list [marié, enfants, salaire];
    • line 89: if there is an error, we send the HTTP code [400 Bad Request] to the client. The JSON response contains the list of errors;
    • lines 99-104: from here on, the request has been checked. We can instantiate the [dao, métier] layers. This instantiation has a cost (reading the database), and it should only be done if we are sure we have a valid request. Constructing the [dao] layer may throw an exception of type [ExceptionImpots];
    • lines 106-108: the error message is often that of the DBMS's PDO driver. On Windows, it is sometimes encoded in Windows-1252 and not in UTF-8. But the [json_encode] function only accepts UTF-8 strings: [JsonResponse] would then throw an exception. The [mb_check_encoding] function checks the encoding of the string and the [mb_convert_encoding] function converts it if necessary. The PHP 7 script used the [utf8_encode] function, deprecated since PHP 8.2;
    • line 111: if an exception occurred, we send the HTTP code [500 Internal Server Error] to the client. This code means that the server was unable to process a request that was nevertheless valid. The response explains the cause of the error;
    • line 117: the tax calculation is delegated to the [métier] layer;
    • lines 119-120: sending the response, with the status code [200 OK] by default.

    <?php

declare(strict_types=1);

// espace de noms
namespace Application;

// dépendances Symfony
use Symfony\Component\HttpClient\HttpClient;
use Symfony\Contracts\HttpClient\Exception\ExceptionInterface;
use Symfony\Contracts\HttpClient\HttpClientInterface;

// la couche [dao] du client : un client HTTP du serveur de calcul de l'impôt
class ClientDao implements InterfaceClientDao
{
    // le trait de la version 5 implémente les méthodes [getTaxPayersData] et [saveResults] de l'interface
    use TraitDao;

    // le client HTTP
    private readonly HttpClientInterface $httpClient;

    // constructeur
    // $urlServer : l'URL du serveur de calcul de l'impôt
    // $user : l'utilisateur qui fait les requêtes, tableau [login, passwd]
    // $httpClientOptions : des options supplémentaires du client HTTP (verify_peer, verify_host...)
    public function __construct(
        private readonly string $urlServer,
        #[\SensitiveParameter] array $user,
        array $httpClientOptions = [],
    ) {
        // le client HTTP : les identifiants de l'utilisateur seront envoyés avec chaque requête
        $this->httpClient = HttpClient::create([
            ...$httpClientOptions,
            "auth_basic" => [$user["login"], $user["passwd"]],
        ]);
    }

    // calcul de l'impôt par le serveur
    #[\Override]
    public function calculerImpot(string $marié, int $enfants, int $salaire): array
    {
        try {
            // on fait la requête au serveur
            $response = $this->httpClient->request("GET", $this->urlServer, [
                "query" => [
                    "marié" => $marié,
                    "enfants" => $enfants,
                    "salaire" => $salaire,
                ],
            ]);
            // le statut de la réponse
            $statusCode = $response->getStatusCode();
            // le document JSON de la réponse, même si le statut est un code d'erreur (paramètre false)
            $json = $response->getContent(false);
        } catch (ExceptionInterface $ex) {
            // le serveur n'a pu être joint
            throw new ExceptionImpots("Erreur de communication avec le serveur ({$ex->getMessage()})", 40, $ex);
        }
        // logs
        // print "$json\n";
        // le serveur envoie la chaîne JSON d'un tableau ["réponse" => qqChose]
        try {
            $réponse = json_decode($json, true, flags: JSON_THROW_ON_ERROR)["réponse"] ?? null;
        } catch (\JsonException $ex) {
            $réponse = null;
        }
        if (!is_array($réponse)) {
            throw new ExceptionImpots("Réponse du serveur invalide [$json]", 41);
        }
        // erreur ?
        if ($statusCode !== 200) {
            // on lance une exception dont le message est la réponse du serveur complétée par son statut HTTP
            $message = json_encode(
                ["statut HTTP" => $statusCode] + $réponse,
                JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES | JSON_THROW_ON_ERROR
            );
            throw new ExceptionImpots($message, 42);
        }
        // on rend la réponse : le tableau [impôt, surcôte, décôte, réduction, taux]
        return $réponse;
    }
}

    Comments

    • line 17: we insert the [TraitDao] trait of version 5, which implements the [getTaxPayersData] and [saveResults] methods. So only the [calculerImpot] method remains to be implemented;
    • line 20: the [Symfony] HTTP client, of the [HttpClientInterface] interface type;
    • lines 26-30: the constructor of the [ClientDao] class receives three parameters:
      • the URL [$urlServer] of the tax calculation server. This is a parameter promoted to an attribute (constructor property promotion);
      • the [$user] array with keys [login] and [passwd], which defines the user making the requests. The [#[\SensitiveParameter]] attribute (PHP 8.2) asks PHP to hide the value of this parameter in the stack traces displayed in the event of an error: the password will not appear in them;
      • additional options for the HTTP client;
    • lines 32-35: we create the HTTP client once and for all, with the options received, to which we add the [auth_basic] option: the user's credentials will be sent with every request. The [...] operator copies the elements of the [$httpClientOptions] array into the options array. The PHP 7 client created a new HTTP client for each request;
    • line 40: the [calculerImpot] method receives the three parameters to send to the tax calculation server;
    • lines 44-50: the server is queried with the three parameters it expects. The [query] option adds these parameters to the URL, after encoding them ([marié] becomes [mari%C3%A9]);
    • line 54: we retrieve the server's JSON response. If we do not pass the [false] parameter to the [getContent] method, then, if the status of the server's response indicates an error (codes 3xx-5xx), the HTTP client throws an exception as soon as we try to get the content of the response. Here, whatever the HTTP status of the response, we want access to its content, which explains the error;
    • lines 55-57: if the server could not be reached, the HTTP client throws an exception of type [ExceptionInterface]. We turn it into an [ExceptionImpots] exception: in this way the client's upper layers only have one type of exception to handle;
    • line 60: in development mode, we can display the server's JSON response;
    • lines 63-68: the server's response is the JSON string of an array [["réponse" => qqChose]]. We retrieve the [qqChose]. If the document received is not JSON (for example an Apache HTML error page), we throw an [ExceptionImpots] exception;
    • lines 71-77: if the HTTP status code is not 200, the server has run into a problem. We then throw an exception of type [ExceptionImpots] whose message is the server's JSON response plus the HTTP code of the response. The [+] operator merges two associative arrays;
    • line 80: we return the result, which is an associative array with the keys [impôt, surcôte, décôte, réduction, taux].

$configFilename = ROOT_DIRECTORY . "/Data/" . ($argv[1] ?? "config-client.json");

// on récupère la configuration
$config = json_decode(file_get_contents($configFilename), true, flags: JSON_THROW_ON_ERROR);

// on inclut les dépendances nécessaires au script : bibliothèques tierces (Symfony) puis fichiers de l'application

    require_once ROOT_DIRECTORY . "/$dependency";
}

// les chemins des fichiers de données
$taxPayersDataFilename = ROOT_DIRECTORY . "/" . $config["taxPayersDataFilename"];
$resultsFilename = ROOT_DIRECTORY . "/" . $config["resultsFilename"];
$errorsFilename = ROOT_DIRECTORY . "/" . $config["errorsFilename"];

// création de la couche [dao]
$clientDao = new ClientDao($config["urlServer"], $config["user"], $config["httpClientOptions"]);
// création de la couche [métier]
$clientMetier = new ClientMetier($clientDao);

// calcul de l'impôt en mode batch
try {
    $clientMetier->executeBatchImpots($taxPayersDataFilename, $resultsFilename, $errorsFilename);
    print "Les résultats ont été enregistrés dans le fichier [{$config["resultsFilename"]}]\n";
} catch (ExceptionImpots $ex) {
    // on affiche l'erreur
    print "Erreur n° {$ex->getCode()} : {$ex->getMessage()}\n";
}

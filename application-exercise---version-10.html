    20. Application Exercise – Version 10

    The previous version showed that tax data, shared by all users of the application, should be stored in a scope-based memory [application]. We will use a Redis server (https://redis.io) to implement this.

    20.1. Redis

    Redis is a server that stores data in memory in the form of [clé, valeur] pairs. It is very fast and widely used by web applications as a cache—that is, as a store for data that is costly to retrieve. The [application] scope memory will be implemented by a Redis server. The PHP scripts that require this application memory will be clients of this server:

    • In [1], a script (PHP) sends a command to the Redis server, for example, to request the value associated with a key;
    • In [2], the Redis server responds.

    The Redis server operates independently of the PHP scripts: the data stored on it remains available from one request to the next, and for all users of the application.

    20.2. Installing Redis

    [Laragon] comes with a Redis server that is disabled by default. You can enable it in the [Laragon] preferences ([Preferences] menu, [Services & Ports] tab) by checking the [Redis] checkbox. Leave the port [6379] as is, as this is the default port used by Redis clients. The Redis server is then started along with the other [Laragon] services (Apache, MySQL...) by clicking the [Start All] button.

    20.3. The Redis client in command mode

    The Redis server can be queried in command mode. Open a [Laragon] terminal and type the command [redis-cli], which launches the Redis server client in command mode. The client then displays the prompt [127.0.0.1:6379>]: it is connected to the Redis server on the local machine (address IP 127.0.0.1) on port 6379. Here is a sample session:

    • Line 3: The Redis client has over 200 commands for communicating with the server. One of them, [command count], displays the exact number of commands available for the version being used;
    • Lines 4–7: We’ll only cover the commands we’ll need in our application, PHP. We’ll use Redis for one thing only: associating a value with a key in Redis’s memory. This is done with the Redis command [set clé valeur]. The value can then be retrieved with the command [get clé]. That’s all we’ll need;
    • lines 8–9: The [exists] command checks whether a key exists: it returns 1 if the key exists, 0 otherwise;
    • lines 10–11: The command [del] deletes a key;
    • lines 12–13: if you request the value of a nonexistent key, you get the value [nil], indicating that the key was not found;
    • line 16: To exit the Redis client, enter the command [quit].

    It may be necessary to clear the entire Redis memory. This is done with the command [flushdb].

    20.4. Installing a Redis client for PHP

    We now need a Redis client for PHP. There are two main ones:

    • the PHP [phpredis] extension, written in C, which must be added to the PHP configuration;
    • the [Predis] library (https://github.com/predis/predis), written in PHP, which is installed with [Composer].

    As with course PHP 7, we will use [Predis], version 3. It is located in the [composer.json] file within the [php8-oct-2026] folder and was installed along with the other course libraries using the [composer install] command. It can be found in the [vendor/predis/predis] folder. The class loader for [Composer] supports it: unlike in course PHP 7, there is no longer a [predis/autoload.php] file to include or a [Predis\Autoloader::register] method to call.

    <?php

// Strict adherence to the declared types of function parameters and return values
declare(strict_types=1);

// namespace
namespace Application;

// Symfony dependencies
use Symfony\Component\HttpFoundation\JsonResponse;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\HttpFoundation\Session\Session;
// Predis dependencies
use Predis\Client as RedisClient;
use Predis\PredisException;
// Class alias: the [dao] layer from version 9 is used with Redis
use Application\ServerDaoWithSession as ServerDaoWithRedis;

// Errors from PHP are not sent to the client (they are logged in the web server log)
ini_set("display_errors", "0");

// server root directory: paths in the configuration file are relative to this directory
const ROOT_DIRECTORY = __DIR__;
// Configuration file path
const CONFIG_FILENAME = ROOT_DIRECTORY . "/Data/config-server.json";

// The configuration is retrieved
$config = json_decode(file_get_contents(CONFIG_FILENAME), true, flags: JSON_THROW_ON_ERROR);

// Include the dependencies required by the script
require_once ROOT_DIRECTORY . "/../../../vendor/autoload.php";
foreach ($config["dependencies"] as $dependency) {
    require_once ROOT_DIRECTORY . "/$dependency";
}

// session: it now contains only the authenticated user’s ID
$session = new Session();
$session->start();

// creating the log file
try {
    $logger = new Logger(ROOT_DIRECTORY . "/" . $config["logsFilename"]);
} catch (ExceptionImpots $ex) {
     // 500 error with no logs—the message must not reveal the server’s file directory structure
    $message = "Echec lors de la création du fichier de logs [{$config["logsFilename"]}]";
    doInternalServerError($message, $config["adminMail"]);
     // completed
    exit;
}

// First log entry
$logger->write("---nouvelle requête");

// retrieving the current request
$request = Request::createFromGlobals();
// Authentication only on the first attempt
if (!$session->has("user")) {
     // log
    $logger->write("Authentification en cours…");
     // credentials sent by the client (null if none were sent)
    $requestUser = $request->getUser();
    $requestPassword = $request->getPassword();
     // Is the user one of the authorized users?
    $trouvé = $requestUser !== null && $requestPassword !== null
        && array_any(
            $config["users"],
            fn(array $user): bool => $user["login"] === $requestUser && hash_equals($user["passwd"], $requestPassword)
        );
    if (!$trouvé) {
         // not found - code 401
        sendResponse(
            ["erreur" => "Echec de l'authentification [$requestUser]"],
            Response::HTTP_UNAUTHORIZED,
            ["WWW-Authenticate" => 'Basic realm="Serveur de calcul des impots"'],
            $logger
        );
         // completed
        exit;
    }
     // The user's authentication is logged in the session
    $session->set("user", $requestUser);
     // log
    $logger->write("Authentification réussie [$requestUser]");
} else {
     // log
    $logger->write("Authentification prise en session…");
}

// We have a valid user—checking the received parameters
$erreurs = [];
// A request must be received GET with three parameters
if ($request->getMethod() !== "GET" || $request->query->count() !== 3) {
    $erreurs[] = "Méthode GET requise avec les seuls paramètres [marié, enfants, salaire]";
}
// marital status
if (!$request->query->has("marié")) {
    $erreurs[] = "paramètre marié manquant";
} else {
    $marié = strtolower(trim($request->query->getString("marié")));
    if (!in_array($marié, ["oui", "non"], true)) {
        $erreurs[] = "paramètre marié [$marié] invalide";
    }
}
// number of children and salary: integers >= 0
$valeurs = [];
foreach (["enfants", "salaire"] as $paramètre) {
    if (!$request->query->has($paramètre)) {
        $erreurs[] = "paramètre $paramètre manquant";
        continue;
    }
    $valeur = trim($request->query->getString($paramètre));
    if (preg_match('/^\d+$/', $valeur) !== 1) {
        $erreurs[] = "paramètre $paramètre [$valeur] invalide";
    } else {
        $valeurs[$paramètre] = (int) $valeur;
    }
}
// any other parameters in the query?
foreach (array_diff(array_keys($request->query->all()), ["marié", "enfants", "salaire"]) as $paramètre) {
    $erreurs[] = "paramètre [$paramètre] invalide";
}
// Errors?
if ($erreurs !== []) {
     // A 400 error code is sent to the client
    sendResponse(["erreurs" => $erreurs], Response::HTTP_BAD_REQUEST, [], $logger);
     // completed
    exit;
}
// log
[$enfants, $salaire] = [$valeurs["enfants"], $valeurs["salaire"]];
$logger->write("paramètres ['marié'=>$marié, 'enfants'=>$enfants, 'salaire'=>$salaire] valides");

// We have everything we need to work
// Scope memory [application]: a Redis server
try {
     // the Redis client
    $redis = new RedisClient($config["redis"]);
     // We connect to the server right away to see if it’s up
    $redis->connect();
} catch (PredisException $ex) {
     // Error 500
    doInternalServerError("[redis], {$ex->getMessage()}", $config["adminMail"], $logger);
     // Done
    exit;
}
// Creating the [dao] layer
$json = $redis->get("taxAdminData");
if ($json === null) {
     // Tax data is retrieved from the database
    $logger->write("données fiscales prises en base de données");
    try {
         // constructing the layer [dao]
        $dao = new ServerDaoWithRedis(ROOT_DIRECTORY . "/" . $config["databaseFilename"]);
         // The tax data string JSON is placed in the scope memory [application]
        $redis->set("taxAdminData", (string) $dao->getTaxAdminData());
    } catch (ExceptionImpots $ex) {
         // Error 500
        doInternalServerError("[dao], {$ex->getMessage()}", $config["adminMail"], $logger, $redis);
         // completed
        exit;
    }
} else {
     // The tax data is retrieved from the scope memory [application]
    $taxAdminData = TaxAdminData::fromArray(json_decode($json, true, flags: JSON_THROW_ON_ERROR));
     // instantiating the layer [dao]
    $dao = new ServerDaoWithRedis($taxAdminData);
     // log
    $logger->write("données fiscales prises dans Redis");
}
// creation of the layer [métier]
$métier = new ServerMetier($dao);
// tax calculation
$result = $métier->calculerImpot($marié, $enfants, $salaire);
// the response is returned
sendResponse($result, Response::HTTP_OK, [], $logger, $redis);
// end
exit;

// --------------------------------------------------------------------------
// Fatal error: an email to the administrator and a 500 response to the client
function doInternalServerError(
    string $message,
    array $adminMail,
    ?Logger $logger = null,
    ?RedisClient $redis = null
): void {
     // The error message from a driver in SGBD may not be encoded in UTF-8 (Windows-1252 on Windows)
    if (!mb_check_encoding($message, "UTF-8")) {
        $message = mb_convert_encoding($message, "UTF-8", "Windows-1252");
    }
     // An email is sent to the administrator
     // [SendAdminMail] catches all exceptions and logs them itself
    (new SendAdminMail($adminMail, $logger))->send($message);
     // Send a 500 error code to the client
    sendResponse(["erreur" => $message], Response::HTTP_INTERNAL_SERVER_ERROR, [], $logger, $redis);
}

// Send the response HTTP to the client
// $result: the array to be sent, in the form ["réponse" => $result]
// $statusCode: the HTTP status of the response
// $headers: the HTTP headers to add to the response
// $logger: the application log (null if it could not be created)
// $redis: the Redis client (null if it has not yet been created)
function sendResponse(
    array $result,
    int $statusCode,
    array $headers = [],
    ?Logger $logger = null,
    ?RedisClient $redis = null
): void {
     // the response JSON
    $response = new JsonResponse(null, $statusCode, $headers);
    $response->setEncodingOptions(JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES | JSON_PRESERVE_ZERO_FRACTION);
    $response->setData(["réponse" => $result]);
     // sending
    $response->send();
     // log
    $logger?->write($response->getContent());
     // Closing the connection to the Redis server
    $redis?->disconnect();
}

    • Lines 15–16: the classes from [Predis] that we’re using. The [Predis\Client] class is the Redis client. We give it the alias [RedisClient], which is more descriptive in our code. [PredisException] is the parent class of all exceptions thrown by [Predis];
    • Line 18: We give the alias [ServerDaoWithRedis] to the [ServerDaoWithSession] class from version 9 to reflect the change in the server script’s implementation. The [ServerDaoWithSession] class can construct the [dao] layer from previously acquired tax data: it does not matter whether the data comes from a session or a Redis server;
    • lines 38–39: the session is retained. There are two pieces of information to keep in mind here:
      • the fact that the user has authenticated successfully. This information has a scope of [session]: it is linked to a specific user and does not apply to other users. It remains in the session;
      • the tax administration data. This information has the scope [application]: it is not linked to a specific user but applies to all users. It is stored on the Redis server;
    • lines 135–145: creation of the client [Predis], which will communicate with the Redis server using the connection parameters from the configuration file:
      • line 140: The client is immediately connected to the server to check if it is responding;
      • if the connection to the Redis server fails, an error response is sent to the client and an email is sent to the application administrator. The error message is prefixed with [[redis]] to indicate the source of the error;
    • line 148: the Redis server is queried for the value of the key [taxAdminData]. The [Predis] client provides a method for each Redis command: the [get] method sends the [get taxAdminData] command. It returns the value of the key, or [null] if it does not exist;
    • line 149: if the key is not found, then the tax data is retrieved from the database;
    • line 156: the key [taxAdminData] is stored in Redis memory, associated with the string JSON from the object [TaxAdminData] obtained from the layer [dao]. The [set] method expects a string as the key’s value. The [(string)] conversion calls the [__toString] method of the [TaxAdminData] class, which returns the string JSON from the object. The PHP 7 script let PHP perform this conversion implicitly; with [declare(strict_types=1)], it is better to write it out;
    • Line 159: If reading from the database fails, return a 500 error and send an email to the administrator; the message is prefixed with [[dao]];
    • lines 164–169: The key [taxAdminData] is in Redis memory. We know that its value is the string JSON from an object [TaxAdminData]:
      • line 165: the string JSON is decoded into an associative array, then the static method [TaxAdminData::fromArray] from version 5 constructs the object [TaxAdminData] from this array, while verifying its data;
      • line 167: the [dao] layer is instantiated with this data;
    • lines 182–187: The function [doInternalServerError] has one additional parameter—the Redis client—which it passes to the function [sendResponse]. When a function has many parameters, they are written one per line;
    • line 221: The function [sendResponse] closes the connection to the Redis server, if it was opened.

    We’ve already mentioned that before each test, the [setUp] method of the test class is re-executed, which means that the [ClientDao] class being tested is instantiated with a nonexistent session cookie for each test. It is therefore as if the 11 tests represented 11 different users, with 11 different sessions:

    • line 5: tax data is retrieved from the database;
    • lines 11, 17: tax data is retrieved from Redis memory. This clearly demonstrates that there is a [application]-scoped memory shared by all users of the application.

    20.8. Viewing the contents of the Redis server

    We have seen that the Redis server can be managed in command mode. The command [get taxAdminData] displays the value of the key [taxAdminData]: we recognize the string JSON as belonging to an object of type [TaxAdminData]:

    [redis-cli] displays the string enclosed in quotation marks, prefixing each quotation mark it contains with the character [\].

    The Redis server can also be managed using a graphical interface. The official tool is [Redis Insight] (https://redis.io/insight), which is free and available for Windows. Once connected to the [127.0.0.1:6379] server, it displays the list of keys stored by the server. By clicking on the [taxAdminData] key, you can see its value, which the tool displays as a JSON object. You can also delete a key, add a new one, or execute [redis-cli] commands in a built-in console.

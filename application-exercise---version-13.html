    24. Application exercise – version 13

    Version 13 brings few changes: it secures access to the application's files. It adds no functionality: the actions, the JSON, XML and HTML responses and the views are those of version 12. What changes is the organization of the files on disk and the configuration of the [Apache] server.

    24.1. The problem

    In the PHP 7 course, one could request the URL of the version 12 configuration file and the browser would display it. Yet this [config.json] file contains sensitive information, such as the credentials of the users authorized to use the application. It must not be accessible to users.

    In our version 12, this file is already protected: it is in the [Data] folder, whose [.htaccess] file, presented with version 8, forbids access to it (directive [Require all denied]). But this is case-by-case protection: we forbid what we thought of forbidding, and everything else is served. And there are still many things that should not be shown. For example, the browser can request a view directly, without going through the main controller:

    24.4. The application's [.htaccess] file

    With [Laragon], the document root of the [Apache] server ([DocumentRoot] directive) is the [www] folder. Everything under [www] can therefore be requested through a URL, and in particular the whole [version-13] folder. To forbid access to everything that is not in the [public] folder, we use a single [.htaccess] file, placed at the root of the application, in the [version-13] folder. Recall that the directives of an [.htaccess] file apply to the folder containing it and to all its subfolders. [Laragon] configures [Apache] so that it reads these files (directive [AllowOverride All]):

    # version 13 : seul le dossier [public] de l'application est accessible par le web
# (Apache 2.4 - le module [mod_rewrite] doit être actif, ce qui est le cas avec Laragon)

# pas de liste du contenu des dossiers
Options -Indexes

# réécriture des URL : les motifs sont comparés au chemin de l'URL relatif au dossier [version-13]
RewriteEngine On
# l'URL du dossier de l'application [.../version-13/] est redirigée vers le dossier [public]
# %1 : le chemin de l'URL demandée, sans le / final, capturé par la condition [RewriteCond]
RewriteCond %{REQUEST_URI} ^(.*)/$
RewriteRule ^$ %1/public/ [R=302,L]
# toute autre URL qui ne désigne pas le dossier [public] ou l'un de ses fichiers est refusée (403 Forbidden)
RewriteRule !^public(/|$) - [F]

    Comments

    • line 5: when a URL designates a folder that has no default document ([index.php], [index.html]), [Apache] may display the list of the folder's files. The [Options -Indexes] directive forbids it to do so;
    • line 8: we use [Apache]'s [mod_rewrite] module, the URL rewriting module, enabled by default in [Laragon]. A [RewriteRule] rule has the form [RewriteRule pattern substitution [options]]. In an [.htaccess] file, the pattern, a regular expression, is compared with the path of the requested URL relative to the folder of the [.htaccess] file. For the URL [http://localhost/php8-oct-2026/scripts-web/impots/version-13/Config/config.json], this path is [Config/config.json];
    • lines 11-12: the 1st rule handles the URL of the application's folder [.../version-13/], whose relative path is empty (pattern [^$]). It redirects the browser (option [R=302]) to the [public] folder and stops processing the rules (option [L], for "last"). The substitution must be a full URL path: it is obtained from [Apache]'s [REQUEST_URI] variable, the path of the requested URL [/php8-oct-2026/scripts-web/impots/version-13/]. The [RewriteCond] condition preceding the rule compares this variable with the regular expression [^(.*)/$]: the part between parentheses, the path without the final /, is then available in the rule under the name [%1]. Thus, the [.htaccess] file does not depend on the location of the application within the [www] folder;
    • line 14: the 2nd rule applies to any URL whose relative path does not start with [public/] and is not exactly [public]: that is the meaning of the [!] placed before the pattern. The substitution [-] means "no substitution" and the [F] option (for "forbidden") makes [Apache] respond with the code [403 Forbidden]. The URL [.../version-13/public], without the final /, must remain allowed: [Apache] (module [mod_dir]) responds to it with a redirection to [.../version-13/public/].

    This file also forbids access to itself: it is not in the [public] folder. Since the path of a URL is normalized by [Apache] before the rules are applied, a URL such as [.../version-13/public/../Config/config.json] is also refused.

    The PHP 7 course placed in each of the folders to be protected an [.htaccess] file containing the two lines [order deny,allow] and [deny from all]. This is the [Apache] 2.2 syntax. [Apache] 2.4 only accepts it thanks to the compatibility module [mod_access_compat], which is destined to disappear. The [Apache] 2.4 syntax is [Require all denied], which we have been using since version 8.

    If we do not want to use the [mod_rewrite] module, a possible variant uses two [.htaccess] files and the [Require] syntax:

    • in the [version-13] folder, an [.htaccess] file containing the single line [Require all denied]: everything is forbidden;
    • in the [public] folder, an [.htaccess] file containing the single line [Require all granted]: the authorization directives of a subfolder replace those of the parent folder, and the entire content of [public] is allowed.

    This variant also works, but the URL [.../version-13/] is then refused instead of being redirected to the [public] folder.

    24.5. In production: the document root is the [public] folder

    The [.htaccess] file is a solution suited to [Laragon], where a single folder, [www], contains many applications. On a production server, things are done differently: the [public] folder is made the document root of the site. The rest of the application is then outside the website's tree: no URL can reach it, and no rule is needed. This is the organization recommended by PHP frameworks.

    With [Apache], this is done by defining a virtual host, i.e. an additional website served by the same [Apache] server. The [Config/vhost-impots-v13.conf] file gives an example:

# à placer dans le dossier [<laragon>/etc/apache2/sites-enabled] (chemins à adapter)
# l'application est alors accessible à l'URL [http://localhost:8013/]
Listen 8013
<VirtualHost *:8013>
    # la racine des documents : seul le contenu de [public] est accessible par le web
    DocumentRoot "C:/laragon/www/php8-oct-2026/scripts-web/impots/version-13/public"
    <Directory "C:/laragon/www/php8-oct-2026/scripts-web/impots/version-13/public">
        # pas de fichier [.htaccess] à lire : la configuration est ici
        AllowOverride None
        Options -Indexes
        Require all granted

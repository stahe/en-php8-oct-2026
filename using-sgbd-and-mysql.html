    12. Using SGBD and MySQL

    We will now write PHP scripts using a MySQL database:

    In the architecture above, the PHP and [1] scripts do not communicate directly with the SGBD (Database Management System) or [3]. Instead, it communicates with an intermediary known as the SGBD driver or the SGBD and [2] drivers. PHP provides a standard interface for these drivers, the [PDO] interface (PHP Data Objects). This interface is implemented by different drivers tailored to each SGBD: one driver for the SGBD MySQL, another for the SGBD PostgreSQL… To switch to a different SGBD, you switch drivers:

    The PDO driver isolates the PHP and [1] scripts from the SGBD and [3, 6] scripts. Since these drivers implement a standard interface, we canexpect that the script PHP [1] will remain unchanged when switching from SGBD MySQL [3] to SGBD, PostgreSQL, and [6]. In reality, this ideal does not exist. In fact, to communicate with SGBD, the PHP script sends SQL commands (Structured Query Language). This language is implemented by all SGBD systems but is incomplete. Consequently, the SGBD systems have added proprietary commands to it. This is a primary cause of incompatibility among SGBD systems. Furthermore, the data types that can be used in databases may differ from one SGBD to another. For example, PostgreSQL supports a much wider range of data types than MySQL. This is a second cause of incompatibility. Another cause is the handling of automatic primary keys (generated by SGBD): virtually every SGBD has its own policy. Etc… There are numerous causes of incompatibility.

    If you want to avoid rewriting the PHP and [1] scripts when transitioning from MySQL and [3] to PostgreSQL and [6], we generally need to insert a new layer between the PHP and [1] scripts and the PDO and [2, 5] drivers, a layer whose purpose is to resolve incompatibilities between the two SGBD files. However, in the simple cases we’ll encounter, this additional layer won’t be necessary.

    We will now use the SGBD MySQL. Its version 8.4 is included in the [Laragon] package that we installed at the beginning of this course.

    If the reader is new to the concepts of databases and the SQL language, they can refer to the document [http://sergetahe.com/cours-tutoriels-de-programmation/cours-tutoriel-sql-avec-le-sgbd-firebird/]. This document uses Firebird SGBD rather than MySQL, but it covers the fundamentals of databases and the SQL language. The MySQL 8.4 documentation is also available at [https://dev.mysql.com/doc/refman/8.4/en/].

    12.1. Creating a Database

    We will now show you how to create a database and a user named MySQL using the [Laragon] tool.

    Once launched, [Laragon] is managed from its main window and menu (right-click in the window or on its icon in the taskbar):

    • The [Démarrer tout] button starts the Apache web server and the SGBD and MySQL services. The [Laragon] window then indicates that each is active, along with its listening port: 80 for Apache, 3306 for MySQL;
    • the [Base de données] button launches the [HeidiSQL] tool, included with [Laragon], which allows you to manage MySQL databases graphically. You can also install the web tool [phpMyAdmin] (Tools / Quick Add menu), which is then accessible via URL and [http://localhost/phpmyadmin];
    • the [Terminal] button opens a command window where the [Laragon] tools (PHP, Composer, MySQL, etc.) can be used directly.

    Course PHP 7 created the database and its user using the mouse with [phpMyAdmin]. Here, we prefer to write the corresponding SQL commands in a text file, called a SQL script.     12.2. Connecting to a MySQL database

    To connect to a SGBD, you must create a [PDO] object. You can use the constructor of the [PDO] class or, starting with PHP 8.4, its static method [connect]. Both accept the same parameters:

    1
2
    $connexion = new PDO(string $dsn, ?string $username = null, ?string $password = null, ?array $options = null);
$connexion = PDO::connect(string $dsn, ?string $username = null, ?string $password = null, ?array $options = null);

    The parameters have the following meanings:

    Parameter
    Meaning
    [$dsn]
    (Data Source Name) a string specifying the nature of the SGBD and its location on the network. The string ["mysql:host=localhost"] indicates that this is a SGBD MySQL running on the local machine. This string may include other parameters, separated by semicolons, such as the listening port of the SGBD, the name of the database to which you want to connect, and the character set used for communication: ["mysql:host=localhost;port=3306;dbname=dbpersonnes;charset=utf8mb4"]
    [$username]
    the username of the user logging in
    [$password]
    their password
    [$options]
    an array of options for the SGBD driver

    Only the first parameter is required. The object created in this way will then serve as the basis for all operations performed on the database to which you have connected. If the object cannot be created, a [PDOException] exception is thrown.

    Comments

    • lines 8–10: the connection parameters;
    • line 14: the connection to SGBD. The [connect] method is used here with the following parameters:
      • a string specifying the type of SGBD and its location. The string ["mysql:host=localhost"] indicates that this is a SGBD MySQL running on the local machine. The port was not specified; port 3306 is therefore used by default. The database name is not specified either. A connection will then be established to the SGBD MySQL, and a specific database can be selected later;
      • a user ID;
      • its password;
    • Line 17: [$connexion::class] is the class name of the object [$connexion]. Starting with PHP 8.4, each driver PDO has its own class, derived from the class [PDO]: [Pdo\Mysql] for MySQL, [Pdo\Pgsql] for PostgreSQL, [Pdo\Sqlite] for SQLite. The [PDO::connect] method creates an object of the class corresponding to DSN. With [new PDO(...)], we would obtain an object of the [PDO] class itself, which works the same way but does not provide access to driver-specific methods. Since we will only use the methods common to all drivers, both notations are acceptable;
    • line 19: The connection is closed by removing the last reference to the PDO object created initially. This happens automatically at the end of the script;
    • line 20: The connection to a SGBD may fail. In this case, a [PDOException] exception is thrown. This exception is derived from the PHP and [RuntimeException] exceptions;
    • Line 21: The exception’s error message is displayed;
    • line 22: the script is terminated with a non-zero exit code, which signals the failure to any calling program.

    <?php

// strict adherence to the declared types of parameters and function return values
declare(strict_types=1);

// database identity
const DSN = "mysql:host=localhost;dbname=dbpersonnes;charset=utf8mb4";
// user credentials
const ID = "admpersonnes";
const PWD = "nobody";

try {
     // connection to the database MySQL
    $connexion = PDO::connect(DSN, ID, PWD);
     // Delete the table [personnes] if it exists
    $sql = "drop table if exists personnes";
    $connexion->exec($sql);
     // Create the table [personnes]
    $sql = "create table personnes (prenom varchar(30) not null, nom varchar(30) not null, "
        . "age integer not null, primary key(nom, prenom))";
    $connexion->exec($sql);
    print "La table [personnes] a été créée\n";
} catch (PDOException $ex) {
     // display error
    print "Erreur : " . $ex->getMessage() . "\n";
} finally {
     // Log out if necessary
    $connexion = null;
}
// end
print "Terminé\n";

    Comments

    • Line 7: This time, DSN refers to the database [dbpersonnes] ([dbname=dbpersonnes]). The parameter [charset=utf8mb4] tells SGBD that the character strings exchanged with it are encoded in UTF-8, the encoding used in our scripts (PHP). This ensures that accented characters are correctly stored in the database and correctly retrieved;
    • line 14: connect to the database. This is always the first step. The result of the connection is a [PDO] object through which database operations will be performed;
    • Line 16: The command SQL [drop table] deletes the table [personnes] from the database [dbpersonnes]. The clause [if exists] prevents an error if the table [personnes] does not exist;
    • Line 17: Execution of the previous command SQL on the database [dbpersonnes] using the method [PDO::exec]. This execution may trigger a [PDOException], which will be intercepted by the [catch] clause;
    • Lines 19–20: This SQL command creates a table named [personnes]. A table contains rows and columns. The columns form what is called the table structure. The rows form the table’s content. A database can contain one or more tables. The table [personnes] will have three columns here:
      • first_name: a person’s first name as a string of up to 30 characters;
      • last name: the last name of the same person as a string of up to 30 characters;
      • age: the person’s age as an integer;
      • The [not null] attribute on a column requires that the column have a value. Failing to provide one results in a [PDOException] error;
      • [primary key(nom, prenom)] defines a primary key for the table [personnes]. A primary key has a unique value for each row in the table. Here, the primary key is obtained by concatenating the columns [nom] and [prenom] from the row. This constraint ensures that the table cannot contain two people with the same first and last names—that is, two people with the same full name. Creating a person with the same name as another in the table triggers a [PDOException];
    • lines 23–25: if a [PDOException] error occurs, the associated error message is displayed;
    • lines 26–28: the [finally] clause is executed in all cases, whether an exception occurs or not, to close the connection to the database.

    In the event of an error, a SQL operation performed with a [PDO] object may either return a specific value (often the Boolean [false]) without reporting anything, or throw an exception. This behavior is controlled by the [PDO::ATTR_ERRMODE] attribute of the connection. In PHP 7, the default mode was the first one: errors were silent, and the PHP 7 procedure requested the second mode using the following statement:

    1
    $connexion->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);

    Starting with PHP 8.0, exception mode is the default: any error in SGBD triggers a [PDOException]. This instruction is therefore no longer necessary, and we will no longer include it. This is also why we wrote [drop table if exists]: in PHP 7, the [drop table personnes] command on a nonexistent table failed silently; in PHP 8, it would throw an exception.

function exécuterCommandes(PDO $connexion, string $sqlFileName, bool $suivi = false, bool $arrêt = true): array
{
     // uses the connection $connexion
     // execute the commands SQL contained in the text file $sqlFileName
     // this file is a SQL command file to be executed one command per line
     // if $suivi is true, each execution of a SQL command is followed by a message indicating whether it succeeded or failed
     // if $arrêt is true, the function stops at the first error encountered; otherwise, it executes all SQL commands
     // the function returns the array of error messages (empty if no errors occurred)

     // The lines of the file are placed in an array, without line breaks or empty lines
    $requêtes = is_readable($sqlFileName)
        ? file($sqlFileName, FILE_IGNORE_NEW_LINES | FILE_SKIP_EMPTY_LINES)
        : false;
     // error?
    if ($requêtes === false) {
        return ["Le fichier [$sqlFileName] n'existe pas ou n'a pu être lu"];
    }
     // Executes the queries one by one—no errors initially
    $erreurs = [];
    foreach ($requêtes as $requête) {
         // Remove leading and trailing spaces
        $requête = trim($requête);
         // empty query?
        if ($requête === "") {
             // moving on to the next query
            continue;
        }
        try {
             // Execute the query—an exception is thrown if an error occurs
            $connexion->exec($requête);
             // Display screen output or not?
            if ($suivi) {
                print "$requête : Exécution réussie\n";
            }
        } catch (PDOException $ex) {
             // An error occurred
            addError($erreurs, $requête, $ex->getMessage(), $suivi);
             // Should we stop?
            if ($arrêt) {
                break;
            }
        }
    }
     // Result
    return $erreurs;
}

    12.7. Using Transactions

    A transaction allows you to group a sequence of SQL commands into a single unit of execution: either all commands succeed, or one of them fails, in which case all preceding SQL commands are rolled back. In other words, when you use a transaction to execute SQL commands, after the transaction completes, the database is in a stable state:

    • either in a new state created by the successful execution of all SQL commands in the transaction;
    • or in the state it was in before the transaction began to be executed.

    function exécuterCommandes(PDO $connexion, string $sqlFileName, bool $suivi = false): array
{
     // uses the connection $connexion
     // executes the commands SQL contained in the text file $sqlFileName
     // this file is a command file containing SQL commands, one per line
     // if $suivi is true, each execution of a SQL command is followed by a message indicating whether it succeeded or failed
     // The SQL commands are executed within a transaction: if any of them fails, the transaction is rolled back
     // and the database is restored to the state it was in before the transaction
     // the function returns the error message array (empty if no errors occurred)

     // The lines from the file are placed in an array, without line breaks or empty lines
    $requêtes = is_readable($sqlFileName)
        ? file($sqlFileName, FILE_IGNORE_NEW_LINES | FILE_SKIP_EMPTY_LINES)
        : false;
     // Error?
    if ($requêtes === false) {
        return ["Le fichier [$sqlFileName] n'existe pas ou n'a pu être lu"];
    }
     // The queries will be executed within a transaction
    $connexion->beginTransaction();
     // The queries are executed one by one—no errors initially
    $erreurs = [];
    foreach ($requêtes as $requête) {
         // removing leading and trailing spaces
        $requête = trim($requête);
         // Empty query?
        if ($requête === "") {
             // Move on to the next query
            continue;
        }
         // The command name SQL: the first word of the query, in lowercase
        $commande = strtolower(explode(" ", $requête, 2)[0]);
        try {
             // query execution—an exception is thrown if an error occurs
             // A command SELECT returns rows; other commands return the number of modified rows
            $résultat = $commande === "select"
                ? $connexion->query($requête, PDO::FETCH_NUM)
                : $connexion->exec($requête);
             // display output on screen or not?
            if ($suivi) {
                print "[$requête] : Exécution réussie\n";
            }
             // Display the execution result
            afficherInfos($commande, $résultat);
        } catch (PDOException $ex) {
             // An error occurred
            addError($erreurs, $requête, $ex->getMessage(), $suivi);
             // Stop at the first error
            break;
        }
    }
     // End of transaction
    if ($erreurs === []) {
         // No errors occurred: the transaction is committed
        $connexion->commit();
    } else {
         // An error occurred: the transaction is canceled
        $connexion->rollBack();
         // Added an error
        addError($erreurs, "", "Transaction annulée", $suivi);
    }
     // result
    return $erreurs;
}

    Summary:

    • A transaction begins with method [PDO::beginTransaction];
    • it is successfully completed using the [PDO::commit] method;
    • it is terminated upon failure using the [PDO::rollBack] method;
    • the [PDO::inTransaction] method indicates whether a transaction is in progress.

    When working with a database, it is good practice to place any SQL operation within a transaction to isolate it from other database users (this is also one of its purposes). A transaction should be as short as possible. Therefore, be sure to end it with a [commit] or a [rollBack], as appropriate. Finally, please note: with MySQL, commands that modify the database structure ([create table], [drop table], etc.) cannot be rolled back. They implicitly commit the current transaction. This is why the [sql2.txt] file contains only [select], [insert], [update], and [delete] commands.

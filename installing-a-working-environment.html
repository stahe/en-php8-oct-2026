    2. Installing a working environment

    The scripts were written and tested in the following environment:

    • an [Apache] web server / [MySQL] DBMS / [PHP] 8.5 environment called [Laragon];
    • the [Visual Studio Code] editor and its [PHP Intelephense] extension;
    • the [Composer] dependency manager, shipped with [Laragon], which installs the PHP libraries used by the course.

    Other tools (the [Mailpit] mail server, the [PostgreSQL] DBMS, the [Redis] server) are only useful in some chapters: their installation is described in the chapters concerned.

    2.1. Installing Laragon

    [Laragon] is a package for [Windows] that brings together several pieces of software:

    • an [Apache] web server. We will use it to write web scripts in PHP;
    • the [MySQL] DBMS (and also [PostgreSQL]);
    • the PHP scripting language, in several versions, including 8.5;
    • a [Redis] server implementing a cache for web applications;
    • the [Composer] tool;
    • a command terminal in which all these tools can be used directly.

    [Laragon] can be downloaded from https://laragon.org/download/. It is free to use, with all its features; a window occasionally invites you to buy a license to support its development, which is optional. Installation presents no difficulty: accept the default choices. [Laragon] is then installed in the [C:\laragon] folder, which we will call <laragon> from now on:

    Launching [Laragon] displays its main window:

    • the [Start All] button launches the [Apache] web server and the [MySQL] DBMS. The window then shows, for each of them, that it is running and which port it listens on: 80 for [Apache], 3306 for [MySQL];
    • the [Web] button displays the page [http://localhost], which corresponds to the [<laragon>/www] folder;
    • the [Database] button launches a database administration tool ([HeidiSQL], shipped with [Laragon]);
    • the [Terminal] button opens a command terminal in which [php], [composer], [mysql]… can be used directly;
    • the [Root] button opens the [Windows] file explorer on the [<laragon>/www] folder. This is where all the web applications served by [Laragon]'s [Apache] server must be placed;
    • a right-click in the window (or on the [Laragon] icon in the taskbar) opens the [Laragon] menu, which gives access to the configuration of each piece of software.

    2.1.1. Choosing PHP 8.5

    [Laragon] can contain several versions of PHP. The version used is chosen in its menu, under [PHP > Version]. Choose version 8.5 (the most recent of the 8.5 series). It is then used both by the [Apache] server and by the [php] command in the terminal.

    For the [php] command to also be usable in [VS Code] terminals, the PHP folder must be in the [Windows] PATH. [Laragon] takes care of this: menu [Tools > Path > Add Laragon to Path]. Then open a new terminal (terminals that are already open do not see the change) and type:

    1
    > php -v

    The command should display the PHP version, 8.5.x.

    2.1.2. Configuring PHP for learning

    PHP is configured by a text file [php.ini], accessible from the [Laragon] menu, under [PHP > php.ini]. While learning, PHP must report all errors, all warnings and all deprecations. Check that the file contains the following lines (or modify them):

    1
2
3
4
5
6
    error_reporting = E_ALL
display_errors = On
display_startup_errors = On
log_errors = On
error_log = C:/laragon/tmp/php_errors.log
date.timezone = Europe/Paris
    • [error_reporting = E_ALL]: PHP reports everything, including the [Deprecated] messages that announce features due to disappear. A production configuration often uses [E_ALL & ~E_DEPRECATED], which hides them: that is not what we want here;
    • [display_errors = On]: the messages are displayed in the script's output (the terminal, or the web page);
    • [log_errors = On]: the messages are also written to the error log;
    • [error_log]: the file of this log. Without this line, a console script writes its log to the terminal itself, and each message would appear there twice (once preceded by [PHP], once without);
    • [date.timezone]: the time zone used by the date functions.

    The course also uses several PHP extensions. They are enabled in the [Laragon] menu, under [PHP > Extensions], or in the [php.ini] file with lines of the form [extension=nom]. The extensions used are: [curl], [mbstring], [openssl], [pdo_mysql], [pdo_pgsql], [fileinfo] and [zip] (the latter is used by [Composer] to unzip the libraries it downloads). After modifying the [php.ini] file, [Apache] must be restarted ([Laragon]'s [Reload] button); console scripts, on the other hand, reread the [php.ini] file each time they are executed.

    The configuration can be checked in a terminal with the command [php --ini] (the [php.ini] file used) and [php -m] (the list of loaded extensions). The first script of the next chapter, [phpinfo.php], displays the whole configuration.

    2.2. Installing VS Code

    [Visual Studio Code] is a free editor from Microsoft, which can be downloaded from https://code.visualstudio.com/. Here it replaces the [NetBeans] IDE used by the PHP 7 course.

    Once [VS Code] is installed, we add support for the PHP language: in the [Extensions] panel (Ctrl+Shift+X), search for and install the [PHP Intelephense] extension. It provides:

    • code completion: PHP functions, classes, their methods and their attributes are suggested as you type;
    • display of the documentation of a function or method when hovering over its name;
    • error detection as you type (undefined variable, wrong type, non-existent method…), underlined in the code and gathered in the [Problems] panel;
    • code navigation: a Ctrl+click on a class or function name opens its definition, including in the libraries of the [vendor] folder.

    [Intelephense] must know the version of PHP used in order to know its new features: in the [VS Code] settings (Ctrl+comma), search for "intelephense php version" and enter 8.5.

    You then work by opening the course code folder in [VS Code] (menu [File > Open Folder]). A terminal is opened with the menu [Terminal > New Terminal]: it is positioned on the open folder, and you type the [php], [composer], [curl]… commands in it. To execute a console script, go to its folder ([cd] command) and type [php nom-du-script.php].

    "type": "project",

    },
    "require-dev": {
        "phpunit/phpunit": "^12.0"
    },
    "config": {
        "sort-packages": true
    }
}
    • line 6: the libraries needed to execute the scripts. Each one is designated by a name of the form [vendor/package] and a version constraint: [^8.0] means "any version 8.x from 8.0 on". Their role is presented in the chapters that use them;
    • line 7: the project requires PHP 8.5 or later;
    • line 15: the libraries needed only for development, here the [PHPUnit] testing framework.

    To install these libraries, open a terminal in the [php8-oct-2026] folder (the [Laragon] terminal, or the [VS Code] one) and type:

    1
    > composer install

    [Composer] then creates a [vendor] folder containing the libraries and their own dependencies, as well as a [vendor/autoload.php] file. A script that wants to use these libraries only has to include this file, which automatically loads their classes the first time they are used. The course scripts do this with a path relative to their own folder, for example:

    1
    require_once __DIR__ . '/../../vendor/autoload.php';

    The [__DIR__] constant designates the folder of the script that uses it: the path therefore depends neither on the folder in which the script is executed nor on where the [php8-oct-2026] folder has been placed.

    We check the installation by displaying the [PHPUnit] version:

    1
2
    > php vendor/bin/phpunit --version
PHPUnit 12.5.37 by Sebastian Bergmann and contributors.

    Now that the working environment has been installed, we can tackle the basics of PHP.

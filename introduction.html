    This document is a product of Anthropic's AI, Claude. It is a rewrite, for the PHP 8 language, of the course Introduction to the PHP 7 language by example written by Serge Tahé in July 2019. It keeps that course's outline, examples and common thread, and changes its language:

    • the 2019 course used PHP 7.3. Since then, PHP has gone through six major versions: 8.0 (2020), 8.1 (2021), 8.2 (2022), 8.3 (2023), 8.4 (2024) and 8.5 (2025). This document uses PHP 8.5;
    • between these two versions, PHP has changed a great deal: many features have appeared (types, enumerations, read-only classes, [match], named arguments…), and many others have become deprecated: they still work, but PHP displays a [Deprecated] message each time they are used, to warn that they will disappear in a future version. The code in this document uses no deprecated feature: all the scripts were executed with PHP 8.5 configured to display all errors, all warnings and all deprecations, and no [Deprecated] message appears in their results;
    • the tools have changed too: the [VS Code] editor replaces the [NetBeans] IDE, the [PHPUnit] testing framework replaces [Codeception], the [curl] command replaces the [Postman] tool, the [Symfony Mailer] library replaces the abandoned [SwiftMailer], and the [Mailpit] mail server replaces [hMailServer], which has also been abandoned.

    This document offers a series of PHP console scripts in various areas (language structures, classes, access to files, databases and the internet). Web programming is approached through web services. In this document, a web service is any web application that produces data (plain text, JSON, XML) rather than HTML pages. These are data servers, not servers of web pages mixing HTML, CSS and JavaScript. The document covers classic web concepts (the HTTP protocol, JSON or XML responses, session management, authentication) that are also used in classic web programming. The last part of the document also builds an HTML web application.

    1.1. The place of PHP in a client / server application

    Nowadays, web applications are often built in client / server mode:

    • in [1], the web browser displays web pages for a user. These pages contain JavaScript implementing a client of a data web service [2] as well as a client of a server of web page fragments [3]. JavaScript frameworks such as [Vue.js], [React] or [Angular] are designed for this;
    • in [2], the web server is a data server. It can be written in any language, for example PHP. It does not produce web pages in the classic sense (HTML, CSS, JavaScript), except perhaps the first time. But this first page can be obtained from a classic web server [3]. The JavaScript of the initial page then generates the application's various web pages by obtaining the data [4] to be displayed from the data server [2]. It can also obtain web page fragments [5] from the web page server [3] to dress up this data;
    • in [4], the user initiates an action;
    • in [6, 7], they receive data dressed up by a web page fragment.

    1.3. The tools used

    The examples were written and tested with the following tools (their installation is described in the next chapter):

    • [PHP] 8.5, configured to report all errors, all warnings and all deprecations;
    • the [Laragon] 8 package, which brings together under [Windows] PHP 8.5, the [Apache] 2.4 web server, the [MySQL] 8.4 and [PostgreSQL] DBMSs, the [Redis] server and the [Composer] dependency manager;
    • the [Visual Studio Code] (VS Code) editor and its [PHP Intelephense] extension;
    • the PHP libraries installed with [Composer]: [symfony/http-foundation], [symfony/http-client], [symfony/mailer], [symfony/mime] 8, [predis/predis] 3, [zbateson/mail-mime-parser] 3 and, for testing, [phpunit/phpunit] 12;
    • the [Mailpit] test mail server and, for the IMAP protocol, an IMAP server (a [Gmail] account, or a local server);
    • the [curl] command-line tool, shipped with [Windows], which displays raw HTTP exchanges;
    • a browser ([Chrome], [Firefox], [Edge]…).

    The scripts in this document are commented and their console execution is reproduced. Additional explanations are sometimes provided. The document requires active reading: to understand a script, you need to read its code, its comments and its execution results. The screenshots of web pages were taken with a programmatically driven browser: they are real pages of the course's applications.

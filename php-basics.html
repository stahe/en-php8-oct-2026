for ($i = 0; $i < count($t); $i++) {
    print "t[$i]=$t[$i]\n";
}
// des tests
for ($i = 0; $i < count($t); $i++) {
    // n'affiche que les chaînes
    if (gettype($t[$i]) === "string") {
        print "t[$i]=$t[$i]\n";
    }
}
// opérateurs de comparaison == et ===
if ("2" == 2) {
    print "avec l'opérateur ==, la chaîne 2 est égale à l'entier 2\n";
} else {
    print "avec l'opérateur ==, la chaîne 2 n'est pas égale à l'entier 2\n";
}
if ("2" === 2) {
    print "avec l'opérateur ===, la chaîne 2 est égale à l'entier 2\n";
} else {
    print "avec l'opérateur ===, la chaîne 2 n'est pas égale à l'entier 2\n";
}
// une comparaison dont le résultat a changé avec PHP 8
if (0 == "abc") {
    print "avec l'opérateur ==, l'entier 0 est égal à la chaîne abc\n";
} else {
    print "avec l'opérateur ==, l'entier 0 n'est pas égal à la chaîne abc\n";
}
// d'autres tests
for ($i = 0; $i < count($t); $i++) {
    // n'affiche que les entiers > 10
    if (is_int($t[$i]) && $t[$i] > 10) {
        print "t[$i]=$t[$i]\n";
    }
}
// une boucle while
$t = [8, 5, 0, -2, 3, 4];
$i = 0;
$somme = 0;
while ($i < count($t) && $t[$i] > 0) {
    print "t[$i]=$t[$i]\n";

    $i++;               // $i = $i + 1
}
print "somme=$somme\n";

    • line 4: asks PHP to strictly check the declared types of function parameters and results. We will come back to this in the section devoted to type changes. For now, just remember that all the course scripts begin this way;
    • line 8: in PHP, variables are not declared. They have a dynamic type that can vary over time. [$nom] represents the variable with identifier [nom];
    • line 10: to write to the screen, you can use the [print] statement or the [echo] statement;
    • line 12: the [[...]] notation is used to define an array. The notation [$tableau[$i]] represents element no. [$i] of the array [$tableau], the first element having no. 0. The older notation [array("un", "deux", 3, 4)] is still accepted, but we will not use it;
    • line 14: the function [count($tableau)] returns the number of elements of the array [$tableau];
    • lines 16-18: a loop. Since it has only one statement, the braces are optional. In the rest of this document, we will always use braces whatever the number of statements;
    • line 17: strings are enclosed in double quotes " or single quotes '. Inside double quotes, variables [$variable] are evaluated (we also say "interpolated"), but not inside single quotes;
    • line 20: the elements of an array can be assigned to several variables in a single operation. Here [$chaine1="chaine1"] and [$chaine2="chaine2"]. This syntax, called destructuring, replaces the [list] function of older versions of PHP: [list($chaine1, $chaine2) = ...] is still accepted;
    • line 22: the . (dot) operator is the string concatenation operator;
    • lines 91-95: the [function] keyword defines a function. A function can be defined anywhere in the script, even after it is used. Here, [string $chaine] indicates that the parameter [$chaine] must be a string and [: void] that the function returns no result. These type declarations are optional in PHP, but we will use them systematically: they document the code and allow PHP (and the editor) to detect errors;
    • line 98: the [mixed] type (PHP 8.0) means "any type". The parameter [$variable] can receive an integer, a string, an array…;
    • line 101: the predefined function [gettype($variable)] returns a string representing the type of [$variable]. The results show that this type can change over time: [$n] is first an integer (integer) and then a string (string);
    • line 105: a function returns a result with the [return] statement. The type of this result is declared after the parentheses: [: int]. The calling code can ignore or retrieve the results of a function;
    • line 112: a function can return several values by gathering them in an array;
    • lines 53-62: the [===] operator compares two elements strictly: they must have the same type and the same value to be equal. The [] operator is less strict: two elements can be equal without being of the same type. In this case, the comparison is made after converting both elements to the same type. It is quite easy to "forget" these implicit conversions and thus end up with unexpected results, such as discovering that a condition is true when you expected it to be false. To avoid this pitfall, we will systematically use the comparison operator [=] (and its opposite [!==]);
    • lines 64-68: an example of these implicit conversions. In PHP 7, the string "abc" was converted to the number 0, and the expression [0 == "abc"] was true! Since PHP 8.0, when a number is compared to a string that does not represent a number, it is the number that is converted to a string, and the expression is false. The behavior of [] has therefore changed from one version to the next: all the more reason to prefer [=];
    • line 72: the [is_int] function returns [true] if its parameter is an integer. Likewise there are [is_string], [is_float], [is_bool], [is_array]… The [&&] operator is the logical AND. You can also use the logical operators [||] (OR) and [!] (NOT). PHP also knows the keywords [and] and [or], but their precedence, lower than that of assignment, holds surprises: we will not use them;
    • line 80: a [while] loop. It stops as soon as the condition is false, here as soon as the array has been traversed or a negative or zero element is encountered;
    • line 88: the [exit] statement stops the execution of the script. The functions that follow are not executed at this point, but they are known to the whole script.

    Note that the script does not end with the [?>] tag that closes PHP code. It is not required. Moreover, in a web context, it can cause problems if it is followed by spaces or end-of-line marks, which are hard to detect because they are not visible in a text editor. The [PSR-12] recommendation in fact requires omitting it in files containing only PHP. So, in the rest of the document, we will always omit it.

    Note: in this document, we will use the [print] keyword to display text on the console. Another way to do the same thing is to use the [echo] keyword. There are subtle differences between these two keywords, but in the context of this document there will be none. So if you prefer to use [echo], go ahead.

    3.3.2. Using VS Code

    To work on the course scripts, open the [php8-oct-2026] folder in [VS Code] (menu [File > Open Folder]). The file tree appears in the explorer, on the left of the window. To execute a script:

    • open an integrated terminal (menu [Terminal > New Terminal]). It opens in the [php8-oct-2026] folder;
    • go to the script's folder: [cd scripts-console/bases];
    • run the script: [php bases-01.php]. The results are displayed in the terminal. You can also, in the explorer, right-click on the [bases] folder and choose [Open in Integrated Terminal].

    If the [php] command is not recognized, the PHP folder is not in the Windows PATH: [Laragon] adds it when you check the corresponding option of its [Tools > Path] menu. The command [php -v] should display version 8.5.

    The [PHP Intelephense] extension analyzes the code as you type and reports problems with a wavy line under the faulty code. Hovering over this line with the mouse displays the message. All the problems of the folder are gathered in the [Problems] panel (menu [View > Problems]). Among the useful warnings:

    • [Undefined variable]: a variable is used without having been initialized. This is often a typo in a variable name;
    • [Undefined function]: a call to a function that does not exist, again often a typo;
    • [Expected type 'int'. Found 'string'.]: an actual parameter does not have the type declared by the function. This is one of the great benefits of type declarations: the error is reported even before execution;
    • [Expected 2 arguments. Found 1.]: the number of actual parameters does not match the definition of the function.

    Hovering over a function name displays its signature (parameters, types, result) and its documentation, including for PHP's predefined functions. For [Intelephense] to know the recent features of the language, check in the [VS Code] settings (menu [File > Preferences > Settings], search for "intelephense php version") that the PHP version indicated is 8.5. While learning the language, it is advisable to fix all the warnings reported. You learn a lot that way.

    [Intelephense] can also format a file (right-click, [Format Document]) according to the [PSR-12] coding recommendations. PSRs (PHP Standard Recommendations) are recommendations for producing standard code and thus facilitating the interoperability and maintenance of code written by different people. They are published by the [PHP-FIG] on the website www.php-fig.org. The [PSR-1] and [PSR-12] recommendations set the rules for writing code. Here are those of [PSR-1]:

    Element
    Rule
    Class constants
    Class constants MUST be written in uppercase with the _ character as separator.
    E.g.: [const TAUX_TVA]
    Methods
    Method names MUST be written in camelCase.
    E.g.: [public function executeBatchImpots()]
    Properties
    Property names SHOULD be written consistently within the same body of code, in StudlyCaps, camelCase or under_score.
    E.g.: [$SalaireAnnuel], [$salaireAnnuel], [$salaire_annuel]
    Side effects
    A file SHOULD either declare new symbols (classes, functions, constants…) with no other side effect, or execute code with side effects, but SHOULD NOT do both.
    Types
    Type names (classes, interfaces…) MUST be written in StudlyCaps. Each type is in a file of its own and in a namespace of at least one level.
    E.g.: [class EtudiantBoursier]

    The side-effects rule says that a PHP file should contain:

    • either the declaration of types (classes, interfaces), functions or constants;
    • or executable code without the declaration of new types.

    For convenience, the examples of this chapter do not follow it: each script is a single file that defines its functions and uses them. Spreading the code over several files would be too cumbersome for basic examples. For the application presented as the common thread of this document, we will try, as soon as it is written with classes, to follow these recommendations as closely as possible.

{

      • line 16: a real (or integer) number other than 0: result [true];

    • line 34: the dictionary is initialized as empty before being filled. PHP would create the array on the first assignment [$dico[$login] = ...], but if the file were empty, the variable would not exist and using it would cause a warning;
    • line 38: [fgets($fic, 1000)] reads the next line of the file, up to 1000 characters. In the operation [while (($ligne = fgets($fic, 1000)) !== false) {...}], there are two successive operations: 1) [$ligne = fgets(...)] 2) [while ($ligne !== false)]. After the last character of the file has been read, the [fgets] function returns the value [false] and the [while] loop stops. The [fgets] function here tries to read at most 1000 characters but stops as soon as an end-of-line mark is encountered. Here, since all lines have fewer than 1000 characters, [fgets] reads one line of text, end-of-line mark included. The PHP 7 course wrote [while ($ligne = fgets($fic, 1000))]: the loop would have stopped prematurely on a last line reduced to "0", with no end-of-line mark, because the string "0" is converted to [false]. The strict comparison [!== false] avoids this trap;
    • line 40: the [cutNewLineChar] function removes any end-of-line characters;
    • line 44: the function [array_shift($tableau)] removes the 1st element of [$tableau] and returns it as its result;
    • line 46: here the result returned by [array_shift] is ignored;
    • line 58: another way to read a text file. The [file] function returns the array of all the lines of the file. With the [FILE_IGNORE_NEW_LINES] option, the end-of-line marks are removed. This is simpler than the [fgets] loop, but the whole file is loaded into memory: for a very large file, reading line by line remains preferable;
    • line 71: the function [is_array($variable)] returns [true] if [$variable] is an array, [false] otherwise;
    • line 84: the end-of-line mark is the string "\r\n" on Windows systems, "\n" on Unix systems. The function [rtrim($chaîne, $caractères)] removes from the end of [$chaîne] all the characters present in [$caractères], here \r and \n. Without a second parameter, [rtrim] removes all "whitespace" (blank, tab, end of line…); the [trim] function does the same thing at both ends of the string.

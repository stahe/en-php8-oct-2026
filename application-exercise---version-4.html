    11.2. Objects Exchanged Between Layers

    We are retaining certain elements from Version 3 exactly as they were:

    • The [ExceptionImpots] exception is the exception that the [dao] layer will throw when it encounters a problem either with data access or with the nature of the data (incorrect data);

// namespace
namespace Application;

// a taxpayer’s data and the results of their tax calculation: an immutable object
final readonly class TaxPayerData
{
    public function __construct(
         // Data required to calculate the taxpayer’s tax
        public string $marié,
        public int $enfants,
        public int $salaire,
         // tax calculation results (null until the tax has been calculated)
        public ?int $impôt = null,
        public ?int $surcôte = null,
        public ?int $décôte = null,
        public ?int $réduction = null,
        public ?float $taux = null,
    ) {
    }

     // returns a copy of the object populated with the tax calculation results
     // $résultats: array [impôt, surcôte, décôte, réduction, taux] returned by the [métier] layer
    public function avecRésultats(array $résultats): static
    {
        return clone($this, [
            "impôt" => $résultats["impôt"],
            "surcôte" => $résultats["surcôte"],
            "décôte" => $résultats["décôte"],
            "réduction" => $résultats["réduction"],
            "taux" => $résultats["taux"],
        ]);
    }

     // string JSON of the object
    public function __toString(): string
    {
        return json_encode(get_object_vars($this), JSON_UNESCAPED_UNICODE | JSON_THROW_ON_ERROR);
    }
}

    Comments

    • The specifications are as follows:
      • Taxpayer data is stored in a text file;
      • the results of the tax calculation are saved in a text file;
      • Any errors are saved in a text file;
      • it is unknown in what format the tax authority’s data is available. For each new format, the [InterfaceDao] interface must be implemented by a new class;
      • Methods of the interface that encounter a fatal error while accessing data must throw a [ExceptionImpots] exception;
    • Line 15: the method that retrieves taxpayer data, [statut marital, nombre d'enfants, salaire annuel]:
      • the first parameter is the name of the text file containing this data;
      • the second parameter is the name of the text file in which any errors encountered are to be logged;
    • Line 14: The type [array] does not specify what the array contains. The documentation comment for [/** @return TaxPayerData[] */] (syntax PHPDoc) specifies that it is an array of [TaxPayerData] objects. PHP ignores this, but the [PHP Intelephense] extension of [VS Code] uses it: it then knows the type of the array elements and can suggest their attributes during data entry;
    • line 18: the method that retrieves data from the tax authority. No parameters are passed to it because we do not know how the data is stored;
    • line 22: the method that saves the tax calculation results to a text file, whose name is passed as a parameter.

    When writing the [InterfaceDao] interface, we know there will be different ways to implement the [getTaxAdminData] method depending on how the tax authority’s data is stored. The [InterfaceDao] interface will therefore be implemented by different classes, each handling a specific storage method for this data (JSON file, database, web service). These classes will, however, share common code: the implementation of the [getTaxPayersData] and [saveResults] methods. As we saw in the chapter on traits, this use case can be implemented in two ways:

    • We create an abstract class C that contains the code common to the derived classes. Class C implements interface I, but certain methods—which must be defined in the derived classes—are declared abstract in class C, which is therefore itself abstract. We then create classes C1 and C2 derived from C, each of which implements the abstract methods of their parent class C in its own way;
    • we create a trait T that is nearly identical to the abstract class C from the previous solution. This trait does not implement the interface I because, syntactically, it cannot. We then create the classes C1 and C2, which implement the interface I and use the trait T. All that remains for these classes is to implement the methods of the interface I that are not implemented by the trait T that they import.

    For this example, we will use a trait [TraitDao]. Version 3 used an abstract class.

    <?php

declare(strict_types=1);

// namespace
namespace Application;

// Implementation of methods from [InterfaceDao] that work with text files
trait TraitDao
{
     // field separator for a line in the taxpayer file (format constant, PHP 8.2)
    private const string SEPARATEUR = ",";

     // Reading taxpayer data
     #[\Override]
    public function getTaxPayersData(string $taxPayersFilename, string $errorsFilename): array
    {
         // taxpayer data table
        $taxPayersData = [];
         // error table
        $errors = [];
         // Opening the taxpayer data file
        $taxPayersFile = is_readable($taxPayersFilename) ? fopen($taxPayersFilename, "r") : false;
        if ($taxPayersFile === false) {
            throw new ExceptionImpots("Impossible d'ouvrir en lecture les déclarations des contribuables [$taxPayersFilename]", 12);
        }
         // The file is open: it must be closed no matter what
        try {
             // Processing the current row of the taxpayer data file
             // which has the format: marital status, number of children, annual salary
            $num = 0;  // current row number
            while (($ligne = fgets($taxPayersFile, 100)) !== false) {
                 // one more line
                $num++;
                 // any end-of-line character is removed
                $ligne = Utilitaires::cutNewLineChar($ligne);
                 // ignore empty lines
                if (trim($ligne) === "") {
                    continue;
                }
                 // the line must contain the three fields: married, children, salary
                $champs = array_map(trim(...), explode(self::SEPARATEUR, $ligne));
                $erreur = count($champs) !== 3;
                if (!$erreur) {
                    [$marié, $enfants, $salaire] = $champs;
                     // the marital status must be "yes" or "no"
                    $marié = strtolower($marié);
                     // The number of children and the salary must be positive integers or zero
                    $erreur = !in_array($marié, ["oui", "non"], true)
                        || !preg_match('/^\d+$/', $enfants)
                        || !preg_match('/^\d+$/', $salaire);
                }
                 // Error?
                if ($erreur) {
                    $errors[] = "la ligne [$num] du fichier [$taxPayersFilename] est erronée";
                } else {
                     // The taxpayer's data is stored
                    $taxPayersData[] = new TaxPayerData($marié, (int) $enfants, (int) $salaire);
                }
            }
             // Is this the end of the file?
            if (!feof($taxPayersFile)) {
                 // The loop was exited due to a read error
                throw new ExceptionImpots("Erreur lors de la lecture de la ligne n° [" . ($num + 1) . "] du fichier [$taxPayersFilename]", 13);
            }
        } finally {
             // Closing the file
            fclose($taxPayersFile);
        }
         // Errors are saved to a text file
        $this->saveLines($errorsFilename, $errors);
         // Function result
        return $taxPayersData;
    }

     // Storing the results
     #[\Override]
    public function saveResults(string $resultsFilename, array $taxPayersData): void
    {
         // Each element [TaxPayerData] is converted to a string JSON using its method [__toString]
        $this->saveLines($resultsFilename, array_map(strval(...), $taxPayersData));
    }

     // saving an array of lines to a text file
    private function saveLines(string $fileName, array $lignes): void
    {
         // If the text file [$fileName] does not exist, it is created; otherwise, it is overwritten
        $data = implode("", array_map(fn(string $ligne): string => "$ligne\n", $lignes));
        if (@file_put_contents($fileName, $data) === false) {
            throw new ExceptionImpots("Erreur lors de l'enregistrement de données dans le fichier texte [$fileName]", 14);
        }
    }
}

    Comments

    • Line 9: Here we are defining a trait, not a class;
    • Line 12: a field separator constant (PHP 8.2), typed (PHP 8.3): the field separator for a line in the taxpayer file. It becomes a constant of the class that uses the attribute and is used with the notation [self::SEPARATEUR];
    • Line 15: Starting with PHP 8.3, the attribute [#[\Override]] is accepted on a trait method. This is verified in the class that uses the trait: here, the method must correspond to a method of the [InterfaceDao] interface implemented by this class;
    • Lines 16–74: The method [getTaxPayersData] implements the method of the same name from the [InterfaceDao] interface. It retrieves the data for taxpayers [statut marital, nombre d'enfants, salaire annuel] from the text file named [$taxPayersFilename]. It returns this data in the form of a [$taxPayersData] array containing elements of type [TaxPayerData] (line 58);
    • The method [getTaxPayersData] is very similar to the method [AbstractBaseImpots::executeBatchImpots] in version 3, with the following differences:
      • The [getTaxPayersData] method only retrieves taxpayer data. It does not perform any tax calculations: that is the role of the [métier] layer;
      • Like the [executeBatchImpots] method, it flags erroneous rows. Here, the errors are first stored in an array named [$errors], which is written to a text file at the end of processing (line 71). Depending on the situation, this array may or may not be empty. An erroneous line no longer triggers an exception: it is up to the calling code to consult the error file;
      • in the case of a fatal error, a [ExceptionImpots] exception is thrown (line 25, line 64);
    • Lines 23–26: The file is opened before the [try / finally] structure. If opening the file fails, an exception is thrown and there is nothing to close. If it succeeds, the [finally] clause (lines 66–69) ensures that the file is closed, regardless of whether an exception occurs. This approach avoids the “Was the file opened?” check found in version 3;
    • Lines 62–65: Note the processing performed upon exiting the read loop. The function [fgets] has the drawback of returning [false] both when the read operation reaches the end of the file and when it fails due to an error. To distinguish between the two cases, we check whether we have reached the end of the file using the function [feof]. If this is not the case, an error has occurred, and an exception is then thrown;
    • lines 78–82: implementation of the [saveResults] method of the [InterfaceDao] interface. Each [TaxPayerData] element in the array is converted to a string by the function [strval], which calls the [__toString] method of the object: this yields its JSON string. [strval(...)] refers to the [strval] function itself (first-class callable, PHP 8.1);
    • lines 85–92: the private method [saveLines] writes an array of lines to a text file, with each line terminated by the line-end character \n;
    • line 89: the function PHP [file_put_contents] writes a string to a text file. It opens the file, writes the string to it, and closes the file. It returns [false] if an error occurs. In this case, PHP also issues a warning. The [@] operator suppresses this warning: the error is reported via the exception thrown on the next line, with a clearer message.

    The class [TraitDao] has implemented two of the methods from the [InterfaceDao] interface: [getTaxPayersData] and [saveResults]. We still need to implement the [getTaxAdminData] method, which retrieves data from the tax authority.

declare(strict_types=1);

// namespace
namespace Application;

// the [métier] layer
class Metier implements InterfaceMetier
{
     // tax authority data
    private readonly TaxAdminData $taxAdminData;

     // The layer [dao] is injected by the manufacturer
    public function __construct(private readonly InterfaceDao $dao)
    {
         // Data required to calculate the tax is retrieved
         // The method [getTaxAdminData] may throw an exception [ExceptionImpots]
         // it is then allowed to propagate back to the calling code
        $this->taxAdminData = $this->dao->getTaxAdminData();
    }

     // tax calculation
    // --------------------------------------------------------------------------
     #[\Override]
    public function calculerImpot(string $marié, int $enfants, int $salaire): array
    {
         // $marié: yes, no
         // $enfants: number of children
         // $salaire: annual salary
         // $this->taxAdminData: tax authority data
        //
         // tax calculation with children
        $result1 = $this->calculerImpot2($marié, $enfants, $salaire);
        $impot1 = $result1["impôt"];
         // tax calculation without children
        if ($enfants !== 0) {
            $result2 = $this->calculerImpot2($marié, 0, $salaire);
            $impot2 = $result2["impôt"];
             // Application of the family quotient cap
            $plafondDemiPart = $this->taxAdminData->plafondQfDemiPart;
            if ($enfants < 3) {
                 // plafondQfDemiPart euros for the first 2 children
                $impot2 = $impot2 - $enfants * $plafondDemiPart;
            } else {
                 // plafondQfDemiPart euros for the first two children, double that amount for subsequent children
                $impot2 = $impot2 - 2 * $plafondDemiPart - ($enfants - 2) * 2 * $plafondDemiPart;
            }
        } else {
            $impot2 = $impot1;
            $result2 = $result1;
        }
         // We use the highest tax amount with the corresponding rate and surcharge
        if ($impot1 > $impot2) {
            $impot = $impot1;
            $taux = $result1["taux"];
            $surcôte = $result1["surcôte"];
        } else {
            $surcôte = $impot2 - $impot1 + $result2["surcôte"];
            $impot = $impot2;
            $taux = $result2["taux"];
        }
         // Calculation of a possible tax reduction
        $décôte = $this->getDecote($marié, $salaire, $impot);
        $impot -= $décôte;
         // Calculation of a potential tax reduction
        $réduction = $this->getRéduction($marié, $salaire, $enfants, $impot);
        $impot -= $réduction;
         // Result
        return [
            "impôt" => (int) floor($impot),
            "surcôte" => (int) $surcôte,
            "décôte" => (int) $décôte,
            "réduction" => (int) $réduction,
            "taux" => $taux,
        ];
    }

    Comments

    • line 9: The [Metier] class implements the [InterfaceMetier] interface, that is, the [calculerImpot] and [executeBatchImpots] methods;
    • line 12: the object of type [TaxAdminData], which encapsulates the tax administration data. This data is required by the business method [calculerImpot];
    • Lines 15–21: The constructor initializes the class’s two attributes:

    11.7. [PHPUnit] Tests

    Visual tests are highly insufficient:

    • we generally limit ourselves to just a few tests;
    • we may not pay close attention during this visual check, and details may slip past us.

    In real-world professional development, tests are written as code and run automatically, often after every code change. The goal is to make the tests as comprehensive as possible. To achieve this, we use testing frameworks.

    Here, we will use [PHPUnit] [https://phpunit.de/], the standard testing framework in PHP. Course PHP 7 used the [Codeception] framework, which was chosen because it integrated with IDE and NetBeans—and which, incidentally, used PHPUnit behind the scenes. We will use only a small portion of the capabilities of PHPUnit. The idea is to have a quick way, after each new version of the application exercise, to verify that it works. Successful tests give the developer confidence in the code they have written. This is an important factor.

    11.7.6. PHPUnit in VS Code

    The easiest way to run the tests in [VS Code] is to use its built-in terminal (Terminal menu / New Terminal): it opens in the project’s [php8-oct-2026] folder, and you type the command [php vendor/bin/phpunit scripts-console/impots/version-04/Tests] there. The up arrow on the keyboard recalls the last command: rerunning the tests after making a code change takes just one keystroke.

    Some useful options for the [phpunit] command:

    • [--testdox]: displays tests as sentences;
    • [--filter testCalculerImpot]: runs only those tests whose names contain the specified text;
    • [--stop-on-failure]: stops at the first failure.

    There are also extensions for [VS Code] that integrate PHPUnit into the editor’s test explorer (for example, the “PHPUnit Test Explorer” extension): these allow you to run a test with a single click and display the results next to the code. They actually execute the same [phpunit] command that we type into the terminal.

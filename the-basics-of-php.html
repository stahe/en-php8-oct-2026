    }
}

if ("2" == 2) {
    print "avec l'opérateur ==, la chaîne 2 est égale à l'entier 2\n";
} else {
    print "avec l'opérateur ==, la chaîne 2 n'est pas égale à l'entier 2\n";

    • line 8: In PHP, variables are not declared. They have a dynamic type that can change over time. [$nom] represents the variable with identifier [nom];
    • line 10: To write to the screen, you can use the statement [print] or the statement [echo];
    • Line 12: The notation [[...]] is used to define an array. The notation [$tableau[$i]] represents element No. [$i] of the array [$tableau], where the first element is numbered 0. The older notation [array("un", "deux", 3, 4)] is still accepted, but we will not use it;
    • line 14: the function [count($tableau)] returns the number of elements in the array [$tableau];
    • lines 16–18: a loop. Since this loop contains only one statement, curly braces are optional. In the rest of this document, we will always use curly braces regardless of the number of statements;
    • line 17: strings are enclosed in double quotes " or single quotes '. Inside double quotes, the variables [$variable] are evaluated (also called “interpolated”), but not inside single quotes;
    • line 20: You can assign the elements of an array to multiple variables in a single operation. Here, [$chaine1="chaine1"] and [$chaine2="chaine2"]. This syntax, called destructuring, replaces the [list] function from older versions of PHP: [list($chaine1, $chaine2) = ...] is still accepted;
    • line 22: the . (period) operator is the string concatenation operator;
    • Lines 91–95: The keyword [function] defines a function. A function can be defined anywhere in the script, even after it has been used. Here, [string $chaine] indicates that the parameter [$chaine] must be a string, and [: void] indicates that the function returns no result. These type declarations are optional in PHP, but we will use them consistently: they document the code and allow PHP (and the editor) to detect errors;
    • line 98: the type [mixed] (PHP 8.0) means “any type.” The parameter [$variable] can accept an integer, a string, an array, etc.;
    • line 101: the predefined function [gettype($variable)] returns a string representing the type of [$variable]. The results show that this type can change over time: [$n] is first an integer and then a string;
    • line 105: a function returns a result using the statement [return]. The type of this result is declared after the parentheses: [: int]. The calling code can ignore or retrieve the results of a function;
    • line 112: a function can return multiple values by grouping them into an array;
    • lines 53–62: The [===] operator performs a strict comparison of two elements: they must have the same type and the same value to be equal. The [] operator is less strict: two elements can be equal without being of the same type. In this case, the comparison is performed after both elements have been converted to the same type. It is quite easy to “overlook” these implicit conversions and thus end up with unexpected results, such as discovering that a condition is true when you expected it to be false. To avoid this pitfall, we will consistently use the comparison operator [=] (and its negation, [!==]);
    • lines 64–68: an example of these implicit conversions. In PHP 7, the string “abc” was converted to the number 0, and the expression [0 == "abc"] was true! Since PHP 8.0, when comparing a number to a string that does not represent a number, the number is converted to a string, and the expression is false. The behavior of [] has therefore changed from one version to the next: all the more reason to prefer [=];
    • Line 72: The function [is_int] returns [true] if its parameter is an integer. Similarly, there are [is_string], [is_float], [is_bool], [is_array]… The operator [&&] is the logical inverse of ET. You can also use the logical operators [||] (OU) and [!] (NON). PHP also supports the keywords [and] and [or], but their lower priority compared to assignment can lead to unexpected results: we will not use them;
    • line 80: a loop [while]. It stops as soon as the condition is false—in this case, as soon as the array is traversed or a negative or zero element is encountered;
    • Line 88: The [exit] statement stops the script from executing. The functions that follow are not executed at this point, but they are recognized by the entire script.

    Note that the script does not end with the [?>] closing tag for the PHP code. It is not essential. Furthermore, in a web context, it can cause problems if it is followed by spaces or line breaks, which are difficult to detect because they are not visible in a text editor. The [PSR-12] recommendation, in fact, specifies that it should be omitted in files containing only PHP. Therefore, in the remainder of this document, we will systematically omit it.

    Note: In this document, we will use the keyword [print] to display text on the console. Another way to do the same thing is to use the keyword [echo]. There are subtle differences between these two keywords, but in the context of this document, there will be none. So if you prefer to use [echo], then go ahead.

    3.3.2. Using VS Code

    To work on the course scripts, open the [php8-oct-2026] folder within [VS Code] ([Fichier > Ouvrir le dossier] menu). The file tree appears in the explorer on the left side of the window. To run a script:

    • open an integrated terminal ([Terminal > Nouveau terminal] menu). It opens in the [php8-oct-2026] folder;
    • navigate to the script’s folder: [cd scripts-console/bases];
    • run the script: [php bases-01.php]. The results are displayed in the terminal. Alternatively, in the file explorer, you can right-click the [bases] folder and select [Ouvrir dans le terminal intégré].

    If the command [php] is not recognized, it means that the PHP folder is not located in the Windows PATH directory: [Laragon] adds it there when you check the corresponding option in its [Outils > Path] menu. The [php -v] command should display version 8.5.

    The [PHP Intelephense] extension analyzes the code as you type and flags problems with a wavy line under the incorrect code. Hovering the mouse over this line displays the message. All issues in the file are listed in the [Problèmes] panel ([Affichage > Problèmes] menu). Among the useful warnings:

    • [Undefined variable]: a variable is being used without having been initialized. This is often a typo in the variable name;
    • [Undefined function]: A function that does not exist is being called; again, this is often a typo;
    • [Expected type 'int'. Found 'string'.]: An actual parameter does not have the type declared by the function. This is one of the major benefits of type declarations: the error is reported even before execution;
    • [Expected 2 arguments. Found 1.]: The number of actual parameters does not match the function’s definition.

    Hovering over a function name displays its signature (parameters, types, return value) and its documentation, including for the predefined functions of PHP. To ensure that [Intelephense] is aware of recent language updates, check the settings for [VS Code] ([Fichier > Préférences > Paramètres] menu, search for “intelephense php version”) to ensure that the specified version of PHP is 8.5. While learning the language, it is advisable to correct all reported warnings. This is a great way to learn.

    [Intelephense] can also format a file (right-click, [Mettre en forme le document]) according to the coding recommendations in [PSR-12]. The PSR (PHP Standard Recommendations) are guidelines for producing standard code, thereby facilitating interoperability and the maintenance of code written by different people. They are published by the [PHP-FIG] on the www.php-fig.org website. The [PSR-1] and [PSR-12] recommendations establish the rules for writing code. Here are the rules from [PSR-1]:

    Element
    Rule
    Class constants
    Class constants DOIVENT must be written in uppercase letters with the _ character as a separator.
    Ex: [const TAUX_TVA]
    Methods
    Method names such as DOIVENT should be written as camelCase.
    Example: [public function executeBatchImpots()]
    Properties
    Property names such as DEVRAIENT should be written consistently within a single codebase, as StudlyCaps, camelCase, or under_score.
    Examples: [$SalaireAnnuel], [$salaireAnnuel], [$salaire_annuel]
    Side Effects
    A DEVRAIT file can either declare new symbols (classes, functions, constants, etc.) without any side effects, or execute code with side effects, but NE, DEVRAIT, and PAS do both.
    Types
    Type names (classes, interfaces, etc.) DOIVENT must be written in StudlyCaps. Each type is in its own file and in a namespace with at least one level.
    Example: [class EtudiantBoursier]

    The side-effects rule states that a file must contain:

    • either declarations of types (classes, interfaces), functions, or constants;
    • or executable code without declarations of new types.

    For simplicity, the examples in this chapter do not follow this rule: each script is a single file that defines its functions and uses them. Splitting the code across multiple files would be too cumbersome for basic examples. For the application presented as the central theme of this document, we will strive to follow these recommendations as closely as possible once it is written using classes.

    5. The classes

    Vocabulary: A class (keyword [class]) is a type PHP. A variable of this type is called an object. An object is an instance (an instance) of a class.

    It is in this chapter that the evolution of PHP between versions 7 and 8 is most evident. PHP 8 introduced a series of new features that make writing classes more concise and safer: typed attributes, constructor parameter promotion, read-only attributes ([readonly]), enumerations ([enum]), property hooks and asymmetric visibility (PHP 8.4), cloning with modification (PHP 8.5)... We introduce these concepts through the examples, following the progression of Course PHP 7: we start with the most basic class and work our way up to a class written according to current best practices.

    5.3. A Person class with no declared attributes

    In PHP 7, a class could use attributes it had not declared: it was sufficient to write [$p->prenom = "Paul";] to create the attribute [prenom] in the object [$p], just as one does with [stdClass]. These dynamic attributes on objects of an ordinary class have been deprecated since PHP 8.2: each time such an attribute is created, the message “Deprecated: Creation of dynamic property Personne::$prenom is deprecated” is displayed. They will be removed in a future version of PHP. The reason is simple: a typo in an attribute name ([$p->prenon = "Paul"]) would silently create a new attribute instead of reporting the error.

    There are three exceptions to this rule:

    • the [stdClass] class, which we just used, still accepts dynamic attributes;
    • a class preceded by the attribute [#[\AllowDynamicProperties]] also accepts them. This attribute was designed to facilitate the migration of legacy code. We will not use it in this course;
    • a class that defines the magic methods [__get] and [__set] decides for itself what to do with an undeclared attribute.

    <?php

// strict adherence to the declared types of function parameters
declare(strict_types=1);

class Personne
{
     // Attributes are not declared one by one:
     // they are stored in a private array
    private array $attributs = [];

     // called when writing an undeclared attribute: $p->x = value
    public function __set(string $nom, mixed $valeur): void
    {
        $this->attributs[$nom] = $valeur;
    }

     // called when reading an undeclared attribute: $p->x
    public function __get(string $nom): mixed
    {
        return $this->attributs[$nom] ?? null;
    }

     // called by isset($p->x)
    public function __isset(string $nom): bool
    {
        return isset($this->attributs[$nom]);
    }

     // method
    public function identite(): string
    {
         // uses attributes that have not been declared
        return "[$this->prenom,$this->nom,$this->age]";
    }
}

// test
// attributes are created by the magic method [__set]
$p = new Personne();
$p->prenom = "Paul";
$p->nom = "Langevin";
$p->age = 48;
// method call
print "personne=" . $p->identite() . "\n";
// isset
print "isset(\$p->age) : " . var_export(isset($p->age), true) . "\n";
print "isset(\$p->adresse) : " . var_export(isset($p->adresse), true) . "\n";
// end
exit;

    Comments

    • Lines 6–38: define a class named [Personne]. A class is a template used to create objects. It consists of attributes and functions called methods;
    • line 10: The only attribute declared for the class is a private array (we’ll soon see the meaning of the keyword [private]). This array will store the “undeclared” attributes;
    • lines 13–16: The magic method [__set] is automatically called by PHP when writing to an attribute that does not exist (or is not accessible). It receives the attribute’s name and the value to be assigned to it. Here, it stores this value in the array [$attributs]. Methods whose names begin with two underscores are called magic methods: they are not called explicitly; instead, PHP calls them;
    • lines 19–22: The magic method [__get] is called when reading an attribute that does not exist. It returns the stored value or [null]. The operator [??] returns its left operand if it exists and is not [null]; otherwise, it returns its right operand;
    • line 25: the magic method [__isset] is called by the function [isset];
    • Line 31: The method [identite] uses three attributes that are not declared in the class. The keyword [$this] refers to the object to which the method is applied. Each call to [$this->prenom] triggers a call to [__get];
    • Line 40: A [$p] object of type [Personne] is created. The keyword [new] is used to create a new object. The operation returns a reference to the created object (i.e., an address). Various notations are possible: [new Personne()], [new Personne], [new personne]. The class name is case-insensitive;
    • lines 41–43: The three attributes required by the [identite] method are created in the [$p] object by the [__set] method;
    • line 45: the [identite] method of the [Personne] class is applied to the [$p] object. In the code for the [identite] method, [$this] references the same object as [$p].

    This technique has its uses (configuration objects, encapsulation of data read from a file), but it is not the standard way to write a class. In a regular class, you declare its attributes.

    5.18. Abstract Classes

    An abstract class is an incomplete class that cannot be instantiated. It must be derived from in order to be usable.

    What is the purpose of an abstract class? Sometimes we have classes that share one or more methods but differ in other methods or attributes. In such cases, it is desirable to group everything they have in common into a parent class. For now, we don’t need an abstract class. But suppose the child classes differ only in one method, M: the method’s signature would be the same in all child classes, but its implementation would differ. To require the child classes to implement method M:

    • we will declare the signature of method M in the parent class. Since the parent class does not know how to implement it, we prefix the method with the keyword [abstract]: this means that the implementation of method M is deferred to the child classes;
    • because the parent class is not fully implemented, it is also declared abstract using the same keyword [abstract]. This means the class can no longer be instantiated. A child class must be created to define the implementation of method M so that the body of the parent class can be used.

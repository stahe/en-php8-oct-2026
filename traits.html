    9. Traits

    Traits are structures analogous to classes. However, they cannot be instantiated: they are intended to be included in classes. Including a trait in a class has the same effect as if the trait’s code had been copied into the class. Code that can be reused in multiple classes is placed in a trait.

    Traits have been available since PHP 5.4. PHP 8 introduced several new features, which we will discuss at the end of this chapter: signature checking for abstract methods (PHP 8.0), trait constants (PHP 8.2), the [#[\Override]] attribute usable in a trait (PHP 8.3).

    <?php

declare(strict_types=1);

class Class04
{
     // constructor with attribute promotion [name]
    public function __construct(private string $name)
    {
    }

     // getter and setter
    public function getName(): string
    {
        return $this->name;
    }

    public function setName(string $name): void
    {
        $this->name = $name;
    }
}

trait Trait04
{
     // attribute
    private string $name;

     // getters and setters
    public function getName(): string
    {
        return $this->name;
    }

    public function setName(string $name): void
    {
        $this->name = $name;
    }
}

class Class05
{
     // inclusion of the trait
    use Trait04;

     // constructor
    public function __construct(string $name)
    {
        $this->name = $name;
    }
}

// test --------------
$class04 = new Class04("Tim");
$class05 = new Class05("Burton");
print $class04->getName() . "\n";
print $class05->getName() . "\n";
// displaying both objects
print_r($class04);
print_r($class05);

    Code comments

    • lines 5–22: definition of the [Class04] class with an attribute [$name] (initialized by the constructor), its getter, and its setter;
    • lines 24–39: We take the code from [Class04]—excluding its constructor—and move it into the trait [Trait04]. This time, the attribute is explicitly declared, along with its type. We do not include the constructor since a trait cannot be instantiated;
    • line 24: the keyword [trait] designates [Trait04] as a trait rather than a class;
    • lines 41–51: We define a class [Class05] that includes the code from the trait [Trait04] and adds a constructor to it, to make the class instantiable;
    • Line 44: The keyword [use], placed inside a class, allows a trait to be included in a class. It should not be confused with the statement [use], which is placed outside any class and imports a name from a namespace;
    • Lines 54–60: Tests show that the classes [Class04] and [Class05] function in the same way.

    <?php

declare(strict_types=1);

trait Trait01
{
     // attribute
    private int $id = 0;

     // method
    public function doSomething(): void
    {
        print "Trait01::doSomething... ($this->id)\n";
    }
}

class Class02
{
     // inclusion of Trait01
    use Trait01 {
         // The method [Trait01::doSomething] is accessible
         // in the class under the name [doSomethingInTrait]
        Trait01::doSomething as doSomethingInTrait;
    }

     // class-specific method
    public function doSomething(): void
    {
         // id attribute
        $this->id += 10;
         // use of the Trait01 method
        $this->doSomethingInTrait();
         // local display
        print "Class02->doSomething\n";
    }
}

class Class03
{
     // inclusion of Trait01
    use Trait01;

     // class-specific method
    public function doSomethingElse(): void
    {
         // id attribute
        $this->id += 10;
         // use of the Trait01 method
        $this->doSomething();
         // local display
        print "Class03->doSomethingElse\n";
    }
}

// test01 ----------------
function test01(): void
{
    $class02 = new Class02();
    $class03 = new Class03();
    $class02->doSomething();
    $class03->doSomethingElse();
}

// test01
print "test01-----------------\n";
test01();

    Comments

    • lines 5–15: a trait defining an attribute [$id] and a method [doSomething];
    • The trait [Trait01] is included in two classes: [Class02] (lines 17–36) and [Class03] (lines 38–53);
    • lines 20–24: inclusion of [Trait01] in [Class02]. The inclusion is followed by a [{...}] block that allows the included methods to be adjusted;
    • line 23: This line resolves a conflict: [Trait01] and [Class02] both have a method named [doSomething]. In this case, the class method takes precedence: the trait method is hidden. The [as] operator makes the [Trait01::doSomething] method accessible in the class under the name [doSomethingInTrait]. Thus, within [Class02], the following notations will be used:
      • [doSomethingInTrait] to call the method [Trait01::doSomething];
      • [doSomething] to call the method [Class02::doSomething];
    • Lines 30–32: The class [Class02] uses the attribute and method of [Trait01] as if they were its own;
    • lines 38–53: the class [Class03] is analogous to the class [Class02]. The inclusion of [Trait01] is simpler here because there is no conflict between the methods of [Trait01] and [Class03].

    <?php

declare(strict_types=1);

// class that replaces the trait
class Class01
{
     // attribute
    private int $id = 0;

     // setter
    public function setId(int $id): void
    {
        $this->id = $id;
    }

     // getter
    public function getId(): int
    {
        return $this->id;
    }

     // method
    public function doSomething(): void
    {
        print "Class01::doSomething... ($this->id)\n";
    }
}

class Class02
{
     // a reference to an instance of Class01, injected by the constructor
    public function __construct(private readonly Class01 $class01)
    {
    }

     // class-specific method
    public function doSomething(): void
    {
         // modification of the Class01 attribute
        $id = $this->class01->getId();
        $id += 10;
        $this->class01->setId($id);
         // use of the Class01 method
        $this->class01->doSomething();
         // local display
        print "Class02->doSomething\n";
    }
}

class Class03
{
     // a reference to an instance of Class01, injected by the constructor
    public function __construct(private readonly Class01 $class01)
    {
    }

     // method local to the class
    public function doSomethingElse(): void
    {
         // Modification of the Class01 attribute
        $id = $this->class01->getId();
        $id += 10;
        $this->class01->setId($id);
         // use of the Class01 method
        $this->class01->doSomething();
         // local display
        print "Class03->doSomethingElse\n";
    }
}

// test01 ----------------
function test01(): void
{
     // Two objects that will access two different instances of [Class01]
    $class02 = new Class02(new Class01());
    $class03 = new Class03(new Class01());
     // verification
    $class02->doSomething();
    $class03->doSomethingElse();
}

// test02 ----------------
function test02(): void
{
     // shared instance of [Class01]
    $class01 = new Class01();
     // two objects that will access the same instance of [Class01]
    $class02 = new Class02($class01);
    $class03 = new Class03($class01);
     // verification
    $class02->doSomething();
    $class03->doSomethingElse();
}

// test01
print "test01-----------------\n";
test01();
// test02
print "test02-----------------\n";
test02();

    Comments

    • Lines 6–28: The class [Class01] replaces the trait [Trait01]. The code for [Trait01] was incorporated into the code for the classes [Class02] and [Class03]. Here, that will not be the case: a reference to a [Class01] object will be injected into the [Class02] and [Class03] classes. The attributes of the [Class01] class will therefore be external to the [Class02] and [Class03] objects. Since the [$id] attribute is private, a getter and a setter must be provided. This is the first difference from a trait: you must create code to access the class’s private attributes. We could have made the [$id] attribute public, but this is not recommended: using a setter to set an attribute’s value allows you to validate it;
    • Line 33: The reference to the object *[Class01] is injected into *[Class02] by its constructor, thanks to parameter promotion. Course PHP 7 used a setter [setClass01]. Injection by the constructor is preferable: the [Class02] object is complete as soon as it is constructed, and since the attribute is [readonly], the reference can no longer be changed;
    • lines 41–45: for any use of the code [Class01], we must go through the attribute [$this->class01];
    • lines 51–70: The class [Class03] is a clone of the class [Class02], except that its method has a different name;
    • lines 73–81: the first test. This involves injecting two different instances of the class [Class01] into the objects [Class02] and [Class03];
    • lines 84–94: The second test injects the same instance of the [Class01] class into the objects [Class02] and [Class03].

    9.4. Grouping Methods in a Trait

    In the previous example, the trait included attributes and methods. Here, we’ll consider the case where it contains only methods. The trait then resembles a factorization of methods that can be used in different classes. Since the trait has no attributes here, we’ll consider the case where the methods it contains operate solely on the parameters passed to them. This is not mandatory: a trait can operate on an attribute [$this->attribut1] without having that attribute itself. In that case, it is up to the classes that use this trait to provide the attribute [$this->attribut1].

    In the case where the trait has only methods that operate solely on parameters passed to them, we will show that the trait can be replaced by a class with the same methods as the trait, declared as static.

    The use of the trait is illustrated by the script [trait-04.php], which reuses the trait from the previous example but removes all attributes:

    We indeed get the same result as with the trait [Trait01], which shows that its use can be avoided. We noted that a trait’s methods can operate on an attribute [$this->attribut1] even if the trait itself does not have that attribute; it is up to the classes that use the trait to provide it. This is an exotic and fragile scenario: it is better to “pass up” the attribute [$this->attribut1] to the trait itself. That way, it will necessarily be part of the attributes of the class using the trait. We’ll see at the end of the chapter that PHP 8 offers a clean solution for requiring something from classes that use a trait: abstract methods.

    9.5. Multiple Inheritance with a Trait

    It is common to read in the literature that traits allow for multiple inheritance: the ability for a class to inherit from multiple classes. The C++ language supports this feature, but neither Java nor C# do, as they only support single inheritance.     <?php

declare(strict_types=1);

trait Trait01
{
     // attribute
    private int $i = 0;

     // shared method
    public function doSomethingInTrait01(): void
    {
         // modification of Trait01::$i
        $this->i++;
         // display
        print "Trait01::doSomethingInTrait01... i=$this->i\n";
    }
}

class Class02
{
     // attribute accessible to derived classes
    protected int $j = 0;

     // method
    public function doSomethingInClass02(): void
    {
         // modification of Class02::$j
        $this->j += 10;
         // display
        print "Class02->doSomethingInClass02... j=$this->j\n";
    }
}

// derived class
class Class03 extends Class02
{
     // inherits from Class02::$j and includes Trait01::$i
    use Trait01;

     // method
    public function doSomethingInClass03(): void
    {
         // uses the method from Trait01
        $this->doSomethingInTrait01();
         // modification of Trait01::$i
        $this->i += 100;
         // Modifying Class03::$j (==Class02::$j)
        $this->j += 1000;
         // display
        print "Class03->doSomethingInClass03... i=$this->i, j=$this->j\n";
    }
}

// test ----------------
(new Class02())->doSomethingInClass02();
(new Class03())->doSomethingInClass03();

    Comments

    • lines 5–18: a trait [Trait01] with an attribute and a method that manipulates it;
    • lines 20–33: a class [Class02] that has nothing to do with the trait [Trait01]. It does not use it;
    • line 23: the sole attribute of [Class02] has the visibility [protected] so that it is accessible in derived classes;
    • Line 36: The class [Class03] extends the class [Class02]. In addition, it incorporates the trait [Trait01] (line 39). Finally, it inherits the attributes and methods of [Class02] and incorporates the attributes and methods of [Trait01]. This is therefore analogous to multiple inheritance.

    9.6. Using a trait instead of an abstract class

    The following use case is common: you create a fairly general interface I that can give rise to multiple implementations. These implementations share common code but differ in other methods. There are two ways to implement this use case:

    • You create an abstract class C that contains the code common to the derived classes. Class C implements interface I, but certain methods—which must be defined in the derived classes—are declared abstract in class C, which is therefore itself abstract. We then create classes C1 and C2 derived from C, each of which implements the abstract methods of their parent class C in its own way;
    • we create a trait T that is nearly identical to the abstract class C from the previous solution. This trait does not implement the interface I because, syntactically, it cannot. We then create the classes C1 and C2, which implement the interface I and use the trait T. All that remains for these classes to do is to implement the methods of the interface I that are not implemented by the trait T that they import.

declare(strict_types=1);

interface Interface1
{
    public function doSomething(): void;

    public function doSomethingElse(): void;
}

abstract class AbstractClass implements Interface1
{
     // attributes accessible to derived classes
    protected int $attr1 = 11;
    protected int $attr2 = 12;

     // getters and setters
    public function getAttr1(): int
    {
        return $this->attr1;
    }

    public function getAttr2(): int
    {
        return $this->attr2;
    }

    public function setAttr1(int $attr1): static
    {
        $this->attr1 = $attr1;
        return $this;
    }

    public function setAttr2(int $attr2): static
    {
        $this->attr2 = $attr2;
        return $this;
    }

     // implemented method
     #[\Override]
    public function doSomething(): void
    {
        print "AbstractClass::doSomething [$this->attr1,$this->attr2]\n";

     // unimplemented method
     #[\Override]

}

// derived class 1
class Class1 extends AbstractClass
{
     // attribute
    private int $attr3 = 13;

     // getter and setter
    public function getAttr3(): int
    {
        return $this->attr3;
    }

    public function setAttr3(int $attr3): static
    {
        $this->attr3 = $attr3;
        return $this;
    }

     // implementation of doSomethingElse
     #[\Override]
    public function doSomethingElse(): void
    {
        print "Class1::doSomethingElse [$this->attr1,$this->attr2,$this->attr3]\n";
    }
}

// derived class 2
class Class2 extends AbstractClass
{
     // attribute
    private int $attr4 = 14;

     // getter and setter
    public function getAttr4(): int
    {
        return $this->attr4;
    }

    public function setAttr4(int $attr4): static
    {
        $this->attr4 = $attr4;
        return $this;

     // implementation of doSomethingElse
     #[\Override]
    public function doSomethingElse(): void
    {
        print "Class2::doSomethingElse [$this->attr1,$this->attr2,$this->attr4]\n";
    }
}

// external function
function useInterfaceWith(Interface1 $interface): void
{
    $interface->doSomething();
    $interface->doSomethingElse();
}

// tests
useInterfaceWith(new Class1());
useInterfaceWith(new Class2());
// "Fluent" setters can be chained
useInterfaceWith((new Class1())->setAttr1(21)->setAttr2(22)->setAttr3(23));

    • lines 5–10: The interface [Interface1] has two methods;
    • line 12: The abstract class [AbstractClass] implements the interface [Interface1]. It has two attributes with their getters and setters, implements the [doSomething] method of the [Interface1] interface (line 43), but does not implement the [doSomethingElse] method. This method is therefore declared abstract (line 50). The abstract class [AbstractClass] cannot be instantiated and, to be useful, must be derived from;
    • Lines 29–39: The setters are “fluent”: instead of returning nothing, they return the object [$this]. This allows for chained calls (line 116). The return type [static] (PHP 8.0) refers to the class of the object on which the method was called: [(new Class1())->setAttr1(21)] is of type [Class1] and not [AbstractClass], which allows [setAttr3]—a method specific to [Class1]—to be called next;
    • Line 54: The class [Class1] extends the abstract class [AbstractClass] and therefore implements the interface [Interface1]. It provides a body for the method [doSomethingElse], which its parent class had not defined. It also adds an attribute to those of its parent class;
    • Line 80: The class [Class2] does the same with another attribute;
    • lines 106–110: The function [useInterfaceWith] receives a type [Interface1] as a parameter and calls both methods of this interface;
    • Lines 113–116: The function [useInterfaceWith] is called with a type [Class1] and then with a type [Class2]. This is correct because both of these types implement the [Interface1] interface.

    <?php

declare(strict_types=1);

// a trait that requires something from the classes that use it
trait TraitCompteur
{
     // trait constant (PHP 8.2)
    public const int PAS = 10;

     // static attribute: each using class has its own
    private static int $nbInstances = 0;

     // instance attribute
    private int $compteur = 0;

     // static trait method
    public static function getNbInstances(): int
    {
        return self::$nbInstances;
    }

     // abstract method: the user class must define it (signature verified since PHP 8.0)
    abstract protected function getNom(): string;

     // to be called by the user class constructor
    private function enregistrer(): void
    {
        self::$nbInstances++;
    }

     // Concrete method that uses the abstract method and the constant
    public function incrémenter(): static
    {
        $this->compteur += self::PAS;
        print "{$this->getNom()} : compteur=$this->compteur\n";
        return $this;
    }
}

class Voiture
{
    use TraitCompteur;

    public function __construct(private string $immatriculation)
    {
        $this->enregistrer();
    }

     // Implementation of the abstract method of the trait
     #[\Override]
    protected function getNom(): string
    {
        return "Voiture[$this->immatriculation]";
    }
}

class Velo
{
    use TraitCompteur;

    public function __construct()
    {
        $this->enregistrer();
    }

     #[\Override]
    protected function getNom(): string
    {
        return "Vélo";
    }
}

// tests
(new Voiture("AB-123-CD"))->incrémenter()->incrémenter();
new Voiture("EF-456-GH");
(new Velo())->incrémenter();
// Each class has its own static attribute
print "nombre de voitures : " . Voiture::getNbInstances() . "\n";
print "nombre de vélos : " . Velo::getNbInstances() . "\n";
// the trait's constant is accessible via the class, not via the trait
print "pas : " . Voiture::PAS . "\n";
try {
    print TraitCompteur::PAS . "\n";
} catch (\Error $ex) {
    print $ex::class . " : " . $ex->getMessage() . "\n";
}
// A class that uses the trait must implement the abstract method
// class Airplane { use TraitCompteur;  } // Fatal error: Class Airplane contains 1 abstract method...

    Comments

    • line 9: Since PHP 8.2, a trait can declare constants. These become constants of the class that uses the trait;
    • line 12: A trait can declare static attributes. Like instance attributes, they are copied into each class that uses the trait: each class has its own instance counter;
    • Lines 18–21: A trait can declare static methods. In the trait’s code, [self] refers to the class that uses the trait;
    • Line 24: A trait can declare abstract methods. Any class that uses the trait must implement them; otherwise, it must itself be declared abstract (see the class [Avion] commented out at the end of the script). Starting with PHP 8.0, the implementation signature (parameter and return types) is verified. This is the proper way to make requirements of the classes that use the trait, rather than assuming they have a particular attribute or method;
    • Lines 33–38: A concrete line drawing method that uses the abstract method [getNom] and the constant [PAS]. It returns [$this] (type [static]) so that it can be chained;
    • Lines 41–56: The class [Voiture] uses the trait, calls the trait’s private method [enregistrer] in its constructor, and implements the abstract method [getNom]. Note the [#[\Override]] attribute on this implementation: it is accepted because the class implements an abstract method of the trait;
    • lines 58–72: the class *[Velo]* does the same;
    • lines 79–80: Each class has its own static attribute [$nbInstances];
    • line 82: the trait’s constant is accessible via the class that uses it;
    • line 84: but not directly via the trait: an error occurs.

    9.8. Conclusion

    From the previous examples, it is clear that use cases where using a trait provides a net benefit are not obvious. In our examples, we can always do without it by replacing it with a class. However, it is useful for factoring out code across different classes, as if that code belonged to a parent class, without consuming the single inheritance available to a class PHP. This is what we will do in version 4 of the application exercise.

    7. Exceptions and Errors

    When a method of a class encounters an unrecoverable error (file does not exist, database not connected, network connection down), it does not display an error on a console (file, database) but throws an exception. Exceptions extend the [\Exception] class. In addition to exceptions, the internal operation of PHP also throws errors whose base class is [\Error]. Both classes implement the PHP and [\Throwable] interfaces.

    PHP 8 has fundamentally changed error handling: many situations that produced a simple warning (and often an absurd result) in PHP 7 now throw an error that can be caught. We’ll see this as we go through the examples.

    The [\Throwable] interface is as follows (see documentation):

    interface Throwable extends Stringable
{
    public function getMessage(): string;
    public function getCode(): int;
    public function getFile(): string;
    public function getLine(): int;
    public function getTrace(): array;
    public function getTraceAsString(): string;
    public function getPrevious(): ?Throwable;
    public function __toString(): string;
}

    The roles of the interface methods are as follows:

    Method
    Purpose
    [getMessage]
    Returns the error message
    [getCode]
    returns the error code (an integer)
    [getFile]
    returns the name of the file where the object was created
    [getLine]
    returns the line number where the object was created
    [getTrace]
    returns the function call stack as an array
    [getTraceAsString]
    returns the call stack as a string
    [getPrevious]
    returns the previous (encapsulated) object [Throwable], or [null]
    [__toString]
    returns a string representation of the object

    Note that the [Throwable] interface extends the [Stringable] interface discussed in the chapter on classes. A class cannot directly implement the [Throwable] interface; it must derive from [\Exception] or [\Error].

    <?php

// Strict adherence to the declared types of function parameters
declare(strict_types=1);

// displays the tree structure of predefined classes that implement the [Throwable] interface
// We limit ourselves to extensions that are always present in PHP 8.5:
// the Core, the standard library, the SPL library, the jSON library, and Random
$extensions = ["Core", "standard", "SPL", "json", "random"];

// the predefined classes of these extensions that implement [Throwable]
$classes = array_filter(
    get_declared_classes(),
    function (string $classe) use ($extensions): bool {
        $reflexion = new ReflectionClass($classe);
        return $reflexion->isInternal()
            && $reflexion->implementsInterface(Throwable::class)
            && in_array($reflexion->getExtensionName(), $extensions, true);
    }
);
sort($classes);

// recursive display of the child classes of the [$parent] class
function afficher(?string $parent, array $classes, string $indentation): void
{
     // the direct child classes of [$parent]
    $filles = array_values(array_filter(
        $classes,
        fn(string $classe): bool => (get_parent_class($classe) ?: null) === $parent
    ));
    foreach ($filles as $i => $fille) {
        $derniere = $i === count($filles) - 1;
        print $indentation . ($derniere ? "└── " : "├── ") . $fille . "\n";
        afficher($fille, $classes, $indentation . ($derniere ? "    " : "│   "));
    }
}

print "Throwable\n";
afficher(null, $classes, "");

    • lines 24–36: a recursive function that displays the direct child classes of class [$parent], then the children of each of those, and so on. The function [get_parent_class] returns [false] for a class with no parent: the operator [?:] then transforms [false] into [null];

    The results show two families:

    • the [Exception] family: these are the exceptions thrown by libraries and application code. It includes:
      • [ErrorException], which converts a warning from PHP into an exception (we’ll use this at the end of the chapter);
      • [JsonException] (PHP 7.3), thrown by [json_encode] and [json_decode] with the [JSON_THROW_ON_ERROR] option;
      • [Random\RandomException] (PHP 8.2), initiated by the random number generation functions;
      • exceptions from the SPL library (Standard PHP Library), a collection of classes and interfaces designed to solve problems frequently encountered by developers. They form two subfamilies:
      • [LogicException] and its derivatives: programming errors that can be resolved by correcting the code: invalid argument ([InvalidArgumentException]), value outside the expected range ([DomainException]), nonexistent method ([BadMethodCallException])...;
      • [RuntimeException] and its variants: errors that can only be detected at runtime: index out of bounds ([OutOfBoundsException]), unexpected value ([UnexpectedValueException]), capacity exceeded ([OverflowException])... ;
    • the [Error] family: these are errors thrown by the PHP engine itself. They include:
      • [TypeError]: a value is not of the expected type (function parameter, typed attribute, return value, operand of an operator, etc.). Its derivative, [ArgumentCountError], indicates an insufficient number of arguments;
      • [ValueError] (PHP 8.0): a value is of the correct type but has an invalid value (for example, a negative or zero length);
      • [ArithmeticError] and its derivative [DivisionByZeroError]: errors in arithmetic operations;
      • [UnhandledMatchError] (PHP 8.0): No branch of the expression [match] is suitable;
      • [AssertionError]: [assert] assertion failed;
      • [CompileError] and its derivative [ParseError]: syntax error in a file loaded by [require] or [include];
      • [FiberError] (PHP 8.1) and [Random\RandomError] (PHP 8.2): errors related to fibers and random number generators, which we will not use.

    The two families are unrelated: a [catch (\Exception $e)] clause does not intercept a [Error] error. Only the [Throwable] interface links them.

    <?php

// strict adherence to the declared types of function parameters
declare(strict_types=1);

// Displays all errors
error_reporting(E_ALL);
ini_set("display_errors", "1");
// wrap the code in a try/catch block
try {
    $var = [];
     // unknown key
    print $var["abcd"];
     // division by zero
    $var = 7 / 0;
    var_dump($var);
     // array with fixed bounds
    $array = new \SplFixedArray(5);
    $array[1] = 2;
    $array[4] = "foo";
     // index out of bounds
    $array[5] = 8;
     // validation
    print "ce message ne sera pas affiché\n";
} catch (\Throwable $ex) {
     // \Throwable is the interface implemented by all errors and exceptions
     // the exception is displayed
    print "erreur, message : " . $ex->getMessage() . ", type : " . $ex::class . "\n";
}

    Comments

    • The script is the one presented in the previous paragraph. However, we have now enclosed the code that could cause errors within a [try / catch] structure: if the code in lines 11–24 causes (throws) an exception or an error, it will be handled by the [catch] clause in lines 25–29;
    • Line 25: The parameter of the [catch] clause is the type of exception or error to be handled. By setting the type to [\Throwable], which is an interface, we indicate that we want to handle any class instance that implements the [\Throwable] interface. Since all error and exception classes implement this interface, the [catch] clause handles all errors and exceptions here;
    • line 15: the statement that triggers the error. As soon as an exception occurs, control is transferred to the [catch] clause. The code that follows in [try] is therefore not executed;
    • line 28: the notation [$ex::class] returns the class name of the object [$ex].

    7.7. Clause [finally]

    The structure [try / catch] may have a third element and become a structure [try / catch / finally]. The code in clause [finally] is executed in the following two cases:

    • the [try] clause does not throw an exception. It is then executed in its entirety, after which execution proceeds to the [finally] clause, which is executed in its entirety;
    • The clause [try] throws an exception. It is then executed up to the statement that throws the exception. Execution then proceeds to clause [catch], which is executed in its entirety. Execution then proceeds to clause [finally], which is executed in its entirety.

    Finally, the code in clause [finally] is still executed. This scenario is useful in the following case:

    • In the [try] clause, the code has acquired resources (files, databases, network connections, queues). These resources are generally expensive. They must therefore be released (most often referred to as “closed”) as soon as possible;
    • if the resources were acquired in [try], their release will be handled in [finally]. This ensures that in all cases (whether an error occurs or not), the acquired resources are returned to the system.

This ensures that the information contained in the encapsulated exception—which was the original cause of the error—is not lost;
    • Lines 24–29: demonstrate how to traverse the stack of exceptions nested within an exception. The method [getPrevious] returns the encapsulated exception or [null] if there is none. The [do ... while] loop executes its body at least once and then continues as long as the condition is true.

// Strict adherence to the declared types of function parameters
declare(strict_types=1);

// Error handler: converts PHP warnings into [ErrorException] exceptions
set_error_handler(function (int $niveau, string $message, string $fichier, int $ligne): bool {
    throw new \ErrorException($message, 0, $niveau, $fichier, $ligne);
});

// An unknown key no longer triggers a simple warning but an exception
$personne = ["nom" => "Langevin"];
try {
    print $personne["prenom"] . "\n";
} catch (\ErrorException $ex) {
    print "Erreur : " . $ex->getMessage() . " (ligne " . $ex->getLine() . ")\n";
    print "niveau E_WARNING : " . var_export($ex->getSeverity() === E_WARNING, true) . "\n";
}
// Same applies to attempting to open a nonexistent file
try {
    $flux = fopen(__DIR__ . "/inexistant.txt", "r");
} catch (\ErrorException $ex) {
    print "Erreur : " . $ex->getMessage() . "\n";
}
// We return to the error handler from PHP
restore_error_handler();
print "fin\n";

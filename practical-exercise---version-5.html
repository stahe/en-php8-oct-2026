    13.3.2. Entities

    Entities are the objects exchanged between the application layers. Three of them come from version 4 and are included without any modifications:

    • the exception [TaxException];
    • the [readonly] [TaxAdminData] class containing tax administration data, constructed using its static methods [fromJsonFile] and [fromArray];

    We are adding a fourth one, the entity [Database], which describes the database.

    13.3.2.1. Why is there no base class [BaseEntity]?

    The PHP 7 course introduced a parent class, [BaseEntity], at this point, from which all entities were derived. It was based on a rule: the attributes of an entity have the same names as the keys in the JSON file that it encapsulates. [BaseEntity] was then able to initialize any entity from a JSON file or an associative array using the following loop:

    1
2
3
    foreach ($arrayOfAttributes as $key => $value) {
  $this->$key = $value;
}

    The entity attributes were declared as [protected] (untyped) so that the parent class could modify them, and each entity added its own getters and setters. We are not adopting this solution:

    • the loop above silently creates a dynamic attribute when a key in the JSON file is misspelled. This has been deprecated since PHP 8.2, and is prohibited for [readonly] classes;
    • Entities could be modified by any layer, via their setters or the [setFromArrayOfAttributes] method. Our entities are immutable: a layer cannot accidentally modify an object it received from another layer;
    • the rule “same names in JSON and in the class” still applies, but PHP 8 uses it directly: the expression [new self(...$data)] converts the array keys into named arguments for the constructor (PHP 8.1). It is PHP that then verifies that no keys are missing, that none are unknown, and that each value is of the correct type. There is no longer any common code to factor out into a parent class.

    Finally, version 4 has already added the [fromArray] method to the [TaxAdminData] class. We will see that this method is sufficient to construct a [TaxAdminData] object from the data read from the database. An important consequence is that the [business] layer from version 4 will be reused without modification: in the PHP 7 course, changes to the entities had required modifying the [business] layer.

declare(strict_types=1);

// namespace
namespace Application;

// a class of utility functions: it can be neither instantiated nor derived
final class Utilities
{
    // private constructor: the class cannot be instantiated
    private function __construct()
    {
    }

    // reads a JSON file and returns its decoded content (JSON objects become associative arrays)
    public static function readJsonFile(string $fileName): mixed
    {
        // we retrieve the content of the file
        $contents = is_readable($fileName) ? file_get_contents($fileName) : false;
        if ($contents === false) {
            throw new TaxException("The file [$fileName] does not exist or cannot be read", 15);
        }
        // we decode the JSON
        try {
            return json_decode($contents, true, flags: JSON_THROW_ON_ERROR);
        } catch (\JsonException $ex) {
            throw new TaxException("The file [$fileName] does not contain valid JSON ({$ex->getMessage()})", 16, $ex);
        }
    }

    // saves a value in JSON format in a text file (created if it does not exist, overwritten otherwise)
    public static function writeJsonFile(string $fileName, mixed $data): void
    {
        // indented JSON, accented characters not escaped, floats always written with a decimal point (0.0)
        $json = json_encode($data, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE | JSON_PRESERVE_ZERO_FRACTION | JSON_THROW_ON_ERROR);
        if (@file_put_contents($fileName, "$json\n") === false) {
            throw new TaxException("Error while saving data to the file [$fileName]", 14);
        }
    }
}

    Comments

    • Lines 17–30: The [readJsonFile] method reads a JSON file and returns its decoded content, which can be of any type ([mixed]): A JSON object returns an associative array, while a JSON array returns a list. The code is the one we wrote in the [TaxAdminData::fromJsonFile] method in version 3. Errors are reported by a [TaxException] with code 15 (unreadable file) or 16 (invalid JSON);
    • lines 33–40: the [writeJsonFile] method writes a value in JSON format to a text file. The [json_encode] options are combined by the [|] operator:
      • [JSON_PRETTY_PRINT] produces an indented, easy-to-read JSON;
      • [JSON_UNESCAPED_UNICODE] writes accented characters as they appear (marié) instead of their code (mari\u00e9);
      • [JSON_PRESERVE_ZERO_FRACTION] writes the real number 0.0 as 0.0 rather than 0: this distinguishes real numbers from integers in the output file;
      • [JSON_THROW_ON_ERROR] triggers a [JsonException] exception if the value cannot be encoded in JSON.

    {
        // the content of the file: an array of objects {married, children, salary}
        // may throw a [TaxException] exception
        $taxpayers = Utilities::readJsonFile($taxPayersFilename);
        if (!is_array($taxpayers) || !array_is_list($taxpayers)) {
            throw new TaxException("The file [$taxPayersFilename] does not contain a JSON array", 17);
        }
        // array of the taxpayers data
        $taxPayersData = [];
        // array of the errors
        $errors = [];
        // we check each of the taxpayers
        foreach ($taxpayers as $number => $taxpayer) {
            $taxpayerErrors = $this->check($taxpayer);
            if ($taxpayerErrors === []) {
                // one more taxpayer
                $taxPayersData[] = new TaxPayerData(
                    strtolower(trim($taxpayer["married"])),
                    (int) $taxpayer["children"],
                    (int) $taxpayer["salary"]
                );
            } else {
                // one more error: we note the number of the incorrect taxpayer in the JSON array
                $errors[] = ["number" => $number, "errors" => $taxpayerErrors];
            }
        }
        // we save the errors in a JSON file
        Utilities::writeJsonFile($errorsFilename, $errors);
        // result of the function
        return $taxPayersData;
    }

    // checking the data of a taxpayer: returns the list of the incorrect attributes
    private function check(mixed $taxpayer): array
    {
        // the taxpayer must be a JSON object
        if (!is_array($taxpayer)) {
            return [["taxpayer" => $taxpayer]];
        }
        $errors = [];
        // the marital status must be yes or no
        $married = $taxpayer["married"] ?? null;
        if (!is_string($married) || !in_array(strtolower(trim($married)), ["yes", "no"], true)) {
            $errors[] = ["married" => $married];
        }
        // the number of children and the salary must be positive or zero integers
        // given as a number (2) or as a string ("2")
        foreach (["children", "salary"] as $key) {
            $value = $taxpayer[$key] ?? null;
            $valid = (is_int($value) && $value >= 0)
                || (is_string($value) && preg_match('/^\s*\d+\s*$/', $value) === 1);
            if (!$valid) {
                $errors[] = [$key => $value];
            }
        }
        return $errors;

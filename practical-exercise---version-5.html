    13.3.2. Entities

    Entities are the objects exchanged between the application layers. Three of them come from version 4 and are included without any modifications:

    • the exception [ExceptionImpots];
    • the [readonly] [TaxAdminData] class containing tax administration data, constructed using its static methods [fromJsonFile] and [fromArray];

    13.3.2.1. Why is there no base class [BaseEntity]?

    Course PHP 7 introduced a parent class, [BaseEntity], at this point, from which all entities were derived. It was based on a rule: the attributes of an entity have the same names as the keys in the JSON file that it encapsulates. [BaseEntity] was then able to initialize any entity from a JSON file or an associative array using the following loop:

    1
2
3
    foreach ($arrayOfAttributes as $key => $value) {
  $this->$key = $value;
}

    The entity attributes were declared as [protected] (untyped) so that the parent class could modify them, and each entity added its own getters and setters. We are not adopting this solution:

    • the loop above silently creates a dynamic attribute when a key in the JSON file is misspelled. This has been deprecated since PHP 8.2, and is prohibited for [readonly] classes;
    • Entities could be modified by any layer, via their setters or the [setFromArrayOfAttributes] method. Our entities are immutable: a layer cannot accidentally modify an object it received from another layer;
    • the rule “same names in JSON and in the class” still applies, but PHP 8 uses it directly: the expression [new self(...$tableau)] converts the array keys into named arguments for the constructor (PHP 8.1). It is PHP that then verifies that no keys are missing, that none are unknown, and that each value is of the correct type. There is no longer any common code to factor out into a parent class.

    Finally, version 4 has already added the [fromArray] method to the [TaxAdminData] class. We will see that this method is sufficient to construct a [TaxAdminData] object from the data read from the database. An important consequence is that the [métier] layer from version 4 will be reused without modification: in course PHP 7, changes to the entities had required modifying the [métier] layer.

declare(strict_types=1);

// namespace
namespace Application;

// a utility class: it is neither instantiable nor derivable
final class Utilitaires
{
     // private constructor: the class cannot be instantiated
    private function __construct()
    {
    }

     // reads a JSON file and returns its decoded content (JSON objects become associative arrays)
    public static function lireFichierJson(string $fileName): mixed
    {
         // retrieves the file’s contents
        $contenu = is_readable($fileName) ? file_get_contents($fileName) : false;
        if ($contenu === false) {
            throw new ExceptionImpots("Le fichier [$fileName] n'existe pas ou ne peut être lu", 15);
        }
         // decodes the JSON
        try {
            return json_decode($contenu, true, flags: JSON_THROW_ON_ERROR);
        } catch (\JsonException $ex) {
            throw new ExceptionImpots("Le fichier [$fileName] ne contient pas du JSON valide ({$ex->getMessage()})", 16, $ex);
        }
    }

     // saves a value in JSON format to a text file (created if it doesn’t exist, overwritten otherwise)
    public static function écrireFichierJson(string $fileName, mixed $data): void
    {
         // Indented JSON, unescaped accented characters, real numbers always written with a decimal point (0.0)
        $json = json_encode($data, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE | JSON_PRESERVE_ZERO_FRACTION | JSON_THROW_ON_ERROR);
        if (@file_put_contents($fileName, "$json\n") === false) {
            throw new ExceptionImpots("Erreur lors de l'enregistrement de données dans le fichier [$fileName]", 14);
        }
    }
}
